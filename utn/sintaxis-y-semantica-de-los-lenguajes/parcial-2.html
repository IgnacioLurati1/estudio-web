    Expresiones regulares

    Expresión regular

    Una expresión regular constituye una forma de representar un lenguaje en forma sintética. No cualquier lenguaje se puede representar mediante una expresión regular, los que son representables mediante una expresión regular se denominan lenguajes regulares. Dada una expresión regular r el lenguaje que representa es L(r). Una expresión regular se construye a partir de expresiones regulares más simples, usando un conjunto de reglas definitorias.

    Apunte «3. Expresiones Regulares», pág. 25

    Reglas de definición

    Reglas de definición de las expresiones regulares

    Las siguientes reglas definen las expresiones regulares del alfabeto V.

    1. ε es una expresión regular, el lenguaje que representa es { ε }, es decir, el conjunto que contiene la cadena vacía.
    2. Si a es un símbolo de V, entonces a es una expresión regular la cual representa el lenguaje { a }, el conjunto que contiene la cadena a.
    3. Suponiendo que r y s son expresiones regulares que representan los lenguajes L ( r ) y L ( s ) entonces: ( r ) | ( s ) es una expresión regular que representa L ( r ) U L ( s ); ( r ) . ( s ) es una expresión regular que representa L ( r ) . L ( s ); ( r ) * es una expresión regular que representa ( L ( r ) ) *; ( r ) es una expresión regular que representa L ( r ).

    La especificación de una expresión regular es un ejemplo de definición recursiva. Las reglas 1 y 2 son la base. La regla 3 proporciona el paso inductivo.

    Apunte «3. Expresiones Regulares», pág. 25

    L = {no; si} es un lenguaje regular

    Con V = {n, o, s, i} y L = {no; si}, L es un lenguaje regular representado por la expresión regular ((n).(o))|((s).(i)).

    Apunte «3. Expresiones Regulares», pág. 25

    Demostración

    Un lenguaje designado por una expresión regular es un conjunto regular.

    Apunte «3. Expresiones Regulares», pág. 25

    Precedencia y propiedades

    Convenciones de precedencia

    Se pueden evitar los paréntesis innecesarios en las expresiones regulares si se adoptan las convenciones: el operador * tiene la mayor precedencia y es asociativo por izquierda; la concatenación tiene la siguiente mayor precedencia y es asociativa por izquierda; | tiene la menor precedencia y es asociativo por izquierda.

    Apunte «3. Expresiones Regulares», pág. 26

    Paréntesis que sobran y paréntesis que no

    (a)|((b)*(c)) = a|b*c. ((n).(o)) | ((s).(i)) = n . o | s . i. En cambio ((n)|(o)) . ((s)|(i)) = (n | o) . (s | i), que es distinto de n | o . s | i, porque esta última designa { n ; os ; i }.

    Apunte «3. Expresiones Regulares», pág. 26

    Expresiones regulares equivalentes

    Si 2 expresiones regulares r y s representan el mismo lenguaje, se dice que son equivalentes ( r = s ).

    Apunte «3. Expresiones Regulares», pág. 27

    Dos equivalencias

    ( a | b ) = ( b | a ). ( a | b )* = ( a* . b* )*, por propiedad de la operación cierre-Kleene.

    Apunte «3. Expresiones Regulares», pág. 27

    Propiedades de las expresiones regulares

    • r|s = s|r: | es conmutativo.
    • r|(s|t) = (r|s)|t: | es asociativo.
    • (r.s).t = r.(s.t): . es asociativa.
    • r.(s|t) = r.s|r.t y (s|t).r = s.r|t.r: . es distributiva sobre |.
    • ε.r = r y r.ε = r: ε es el elemento identidad en la concatenación (elemento neutro).
    • r* = (r|ε)*: ε es el elemento identidad.
    • r** = r*: * es idempotente.

    Apunte «3. Expresiones Regulares», pág. 27

    Dónde falla la concatenación

    La lista de propiedades trae la conmutatividad solo para |. La concatenación aparece como asociativa y distributiva, y para cadenas el apunte escribe x.y ≠ y.x.

    Fuente: apunte «2. Lenguajes», pág. 21, y apunte «3. Expresiones Regulares», pág. 27.

    Abreviaturas y definiciones regulares

    Definición regular

    Una definición regular permite presentar una expresión regular de un modo más comprensible o manejable. Dado un alfabeto V, una definición regular es una secuencia de definiciones de la forma <d1> → r1, <d2> → r2, …, <dn> → rn (→ significa designa o denomina), donde cada <di> es un nombre distinto y cada ri es una expresión regular sobre los símbolos de V U { d1, d2, …, di-1 } (los símbolos básicos y los nombres previamente definidos).

    Apunte «3. Expresiones Regulares», pág. 27

    Identificadores de Pascal

    letra → A | B | … | Z | a | b | … | z, digito → 0 | 1 | … | 9, id → letra . ( letra | digito ) *. Es el lenguaje de los identificadores de Pascal, L . (L U D)*.

    Apunte «3. Expresiones Regulares», pág. 27

    Abreviaturas en la notación

    1. «Uno o más casos». El operador + significa «uno o más casos de». La expresión regular a+ representa al conjunto de todas las cadenas de 1 o más a. Entonces: r r* = r+, r* = r+ | ε, ( L(r) )* = ( L(r) )+ U {ε}.
    2. «Cero o un caso». El operador ? significa «cero o un caso de» (op. unario). Entonces: r | ε = r?, (r)? representa L(r) U {ε}.
    3. «Clases de caracteres». Se puede abreviar una expresión regular a | b | c mediante la notación [ a b c ] o [ a – c ].

    Apunte «3. Expresiones Regulares», pág. 28

    Dígitos

    digito → 0 | 1 | … | 9 se abrevia digito → [ 0 – 9 ]. digitos → digito . digito* se abrevia digitos → digito+.

    Apunte «3. Expresiones Regulares», pág. 28

    Cómo pasar de una oración a una e.r.

    El apunte «2. Lenguajes» da un ejemplo en lenguajes: L.(L ∪ D)*, con L las letras y D los dígitos, son las cadenas de letras y dígitos que empiezan con una letra. Ahí se ve el método.

    • Lo que dice «empieza con» o «termina con» es un factor fijo al principio o al final.
    • Lo que dice «cualquier cosa» es una cerradura sobre los símbolos permitidos.
    • «Una o más» es +. «Ninguna o más» es *.

    Fuente: apunte «2. Lenguajes», pág. 24, y apunte «3. Expresiones Regulares», pág. 28.

    Para saber si ε está en el lenguaje de una e.r., usá dos definiciones. Por la concatenación (L.M = {r.t}), ε está en un producto solo si está en los dos factores. Por la cerradura, ε siempre está en r*.

    Finito o infinito, y la palabra más corta

    Un lenguaje es infinito si hay una cerradura (* o +) que se puede repetir sin límite. Es finito si solo tiene alternativas y concatenaciones. La palabra más corta es la que usa el mínimo de cada factor.

    Gramáticas formales

    Una gramática es un modelo matemático con las reglas que describen cómo generar todas las palabras de un lenguaje y solo esas. Sirve para dos cosas: decidir si una sentencia pertenece al lenguaje y describir su estructura.

    Gramática

    Una gramática utiliza dos conjuntos disjuntos de símbolos (el de los terminales VT y el de los no terminales VN) y en general se la puede representar como un conjunto de 4 elementos: G = {VT, VN, P, S}. VT U VN = alfabeto de símbolos gramaticales. VT ∩ VN = { }.

    • VT. El alfabeto con el que están construidas sus palabras. Es un conjunto de símbolos denominados terminales. Por convención los escribiremos con letras minúsculas y dígitos.
    • VN. El alfabeto que será utilizado como auxiliar en el proceso de formación de cadenas (derivación), pero no formarán parte de las cadenas del lenguaje. Por convención se escriben con letras mayúsculas.
    • S. Un símbolo inicial, «start», es un símbolo especial que pertenece a los no terminales. Es el símbolo del que partirá la obtención de cualquiera de las palabras del lenguaje (se lo denomina axioma de la gramática).
    • P. Un conjunto de producciones, que representan cómo se realiza la transformación desde los símbolos no terminales a las palabras del lenguaje. En P, cada producción es un par (α, β) tal que su vinculación responde a la forma general α → β, donde α y β son cadenas y la → significaría es sustituida por.

    Una cadena del lenguaje no contendrá símbolos no terminales y el lenguaje generado por una gramática = L(G) es el conjunto de todas las palabras (o sentencias de la gramática) que se pueden obtener a partir del axioma o símbolo inicial de la gramática por aplicación de derivaciones.

    Apunte «4. Gramáticas», pág. 2

    El orden de los componentes cambia

    En el apunte aparecen G = {{0,1},{A,B},P,A} y G = {VT, VN, P, S}. La formativa del 09/06/26 escribe G = { {S,T,Q}, {a,b}, {producciones}, S }, con los no terminales primero. Para ubicarte, mirá el contenido de cada conjunto. El de mayúsculas son los no terminales y el de minúsculas son los terminales.

    Derivaciones

    Derivación

    La derivación es un proceso que apunta a obtener las palabras del lenguaje, por lo tanto, derivar una cadena es ir sustituyendo una a la vez, las subpartes de ella que coincidan con el α de una producción por el β de la misma. La palabra queda definitivamente formada cuando la constituyen sólo símbolos terminales.

    Apunte «4. Gramáticas», págs. 2 y 3

    Forma sentencial y sentencia

    Se llama forma sentencial de una gramática a una derivación de la misma (es decir a cualquier estadio intermedio de la formación de las palabras del lenguaje); se trata de una cadena formada por símbolos terminales y no terminales. Así S y γαδ son formas sentenciales.

    Se llama sentencia o frase o instrucción del lenguaje a cualquier cadena que sea el resultado último de una derivación a partir de un símbolo inicial y que está formada sólo por símbolos terminales.

    Apunte «4. Gramáticas», pág. 3

    G = { {0, 1}, {A, B}, P, A }

    Con P = {(A → B1), (A → 1), (B → A0)}, una secuencia es A ⇒ B1 ⇒ A01 ⇒ B101 ⇒ A0101 ⇒ 10101. El lenguaje es L = {1(01)ⁿ siendo n = 0, 1, 2, ...}.

    Apunte «4. Gramáticas», págs. 3 y 4

    Derivación por la izquierda y por la derecha

    Derivación por la izquierda: consiste en reemplazar el no terminal de más a la izquierda. Derivación por la derecha: consiste en reemplazar el no terminal de más a la derecha.

    Apunte «4. Gramáticas», pág. 4

    G = ({a, b}, {S, A, B}, S, P)

    Con P = {(S → aABAa), (A → ε), (A → aA), (B → ε), (B → bB)}. Por la izquierda: S ⇒ aABAa ⇒ aBAa ⇒ aAa ⇒ aa. Por la derecha: S ⇒ aABAa ⇒ aABa ⇒ aAa ⇒ aa.

    Apunte «4. Gramáticas», pág. 4

    El apunte compara una producción con una llamada a una función. A → B1 dice «para armar una A, armá una B y después pegale un 1». Derivar es ir resolviendo las llamadas hasta que no queda ninguna.

    Un lenguaje, varias gramáticas

    Gramática y lenguaje

    Toda gramática genera un único lenguaje, pero distintas gramáticas pueden generar el mismo lenguaje, por eso no podemos pensar en clasificar las gramáticas por el lenguaje que generan, por este motivo tenemos que pensar en clasificaciones basadas en la forma de la gramática, más que en la naturaleza del lenguaje que generan.

    Apunte «4. Gramáticas», pág. 5

    Jerarquía de Chomsky y máquinas

    Noam Chomsky ordenó las gramáticas en cuatro tipos. Cada tipo agrega restricciones al anterior, así que los lenguajes de un tipo están contenidos en los del anterior.

    TipoNombreForma de las produccionesLenguajeMáquina
    0Sin restriccionesα → β, con α con al menos un símbolo (no vacía) y β cualquier cadenaIrrestrictoMáquina de Turing
    1Dependiente del contextoαAβ → αγβ, con A no terminal, α y β cadenas cualesquiera y γ no vacíaDependiente del contextoAutómata linealmente acotado (ALA)
    2Libre del contextoA → γ, con A no terminal y γ no vacíaIndependiente del contextoAutómata de pila (push-down)
    3Regular (lineal)A → αB y A → α (por la derecha), o A → Bα y A → α (por la izquierda), con α terminales. Se admite S → εRegularAutómata finito

    Tipo 0 o Gramática sin restricciones

    En este caso cada producción es de la forma α → β donde α ϵ (VT U VN)+ (no habrá producción de la forma ε → β) y β ϵ (VT U VN)*.

    G1 de tipo 0

    G1 = (VN = {S}, VT = {0, 1}, S, P) con S → 000S111 y 0S1 → 01.

    Apunte «4. Gramáticas», pág. 6

    Tipo 1 o Gramática Dependiente del Contexto

    En este caso cada producción es de la forma αAβ → αγβ donde A ϵ VN; α, β ϵ (VT U VN)*, es decir α y β son cadenas que contienen a cualquier símbolo de la gramática, sea o no terminal e inclusive a la cadena vacía; γ ϵ (VT U VN)+, es decir γ contiene símbolos terminales y no terminales y NO podría ser vacía.

    A puede ser sustituido por γ si está acompañada de α por la izquierda y de β por la derecha.

    Sobre estas producciones se impone la restricción de que cualquier derivación contiene mayor cantidad de símbolos que la cadena en la que se hizo la sustitución. Esta propiedad es fácilmente demostrable.

    Si bien γ no puede ser la cadena vacía se admite una excepción en la regla S → ε (siendo S el axioma de la gramática). Como consecuencia se tiene que la palabra vacía pertenece al lenguaje generado por la gramática sólo si contiene esta regla.

    Todo lenguaje formal generado por una Gramática dependiente del Contexto y que no puede ser generado por una gramática de menor jerarquía, se llama Lenguaje Dependiente del Contexto.

    Demostración

    Siendo que:

    por la definición de estas producciones ⇒ | A | ≥ 1 ⇒ | αAβ | ≥ 1

    por la característica definida para γ, γ ≠ ε ⇒ | γ | ≥ 1 ⇒ | αγβ | ≥ 1

    ∴ se demuestra que |αAβ| ≤ |αγβ|.

    Una gramática de tipo 1

    G = ({a, b}, {S, A}, S, P) con P = {(S → aS), (S → aA), (A → ba), (A → aS), (A → b)}. En estas producciones el 1er. miembro es un no terminal y está sólo (α y β son vacíos). El 2do. miembro de las producciones contiene terminales y no terminales y estos están solos, es decir, van acompañados por vacío igual que en el primer miembro.

    Apunte «4. Gramáticas», pág. 7

    Tipo 2 o Gramática Independiente o Libre del Contexto

    En este caso cada producción es de la forma A → γ donde A ϵ VN y γ ϵ (VT U VN)+, es decir γ NO podría ser vacía. A puede sustituirse por γ independientemente de las cadenas por las que esté acompañada.

    La restricción es: la cantidad de símbolos que forman la cadena del lado izquierdo es siempre uno.

    Apunte «4. Gramáticas», pág. 8

    Tipo 3 o Gramática Lineal o Regular

    En este caso cada producción es de la forma A → αB y A → α, o A → Bα y A → α, donde A, B ϵ VN y α ϵ VT.

    La cadena sustituta, que está en el miembro derecho de las producciones nunca será vacía, por lo tanto puede ser una secuencia de terminales con un no terminal como sufijo (gramática regular por la derecha) o con un no terminal como prefijo (gramática regular por la izquierda) o simplemente una secuencia de terminales.

    Apunte «4. Gramáticas», pág. 11

    Regular por la derecha

    G = { {a, b}, {S, A}, S, P } con P = {(S → bbS), (S → aaA), (A → aaA), (A → bb)}. Una derivación es S ⇒ bbS ⇒ bbaaA ⇒ bbaabb, y L = { (bb)ⁿ (aa)ᵏ bb siendo n ≥ 0 y k ≥ 1 }.

    Apunte «4. Gramáticas», págs. 11 y 12

    Clasificá por el tipo más restrictivo que se cumpla

    Como «cada gramática surge de aplicar restricciones al tipo anterior», una gramática de tipo 3 también cumple las formas de los tipos 2, 1 y 0. Buscá el tipo más alto (el 3) que cumpla todas las producciones. Basta con una producción que rompa la forma para bajar un nivel.

    Fuente: apunte «4. Gramáticas», pág. 5.

    Regular contra libre del contexto

    Lenguajes regulares y GLC

    La clase de lenguajes generados por Gramáticas Libres de Contexto (GLC) es más amplia que la clase de lenguajes definidos por Expresiones Regulares. Esto significa que todos los lenguajes regulares pueden ser generados por GLC, como así también algunos lenguajes no regulares (por ejemplo, {aⁿ bⁿ} y Palíndromos).

    Tipo de Chomsky y lenguaje de una gramática2° autotest 2024 y formativa 09/06/26

    Dan un conjunto de producciones y piden el tipo. Otras preguntas piden si el lenguaje que genera es finito o infinito, qué conjunto de palabras genera, y si una gramática genera una palabra dada. La del tipo y la del lenguaje traen la clave del aula en Ejercicios.

    Autómatas finitos

    Un autómata finito (AF) es una máquina que lee una cadena de entrada y responde sí o no según pertenezca o no al lenguaje. Tiene una cinta de entrada, un cabezal que avanza en un solo sentido y un control de estados. La cadena se acepta si el cabezal termina en un estado final.

    Hay estados de inicio, finales (de aceptación) e intermedios. Fuente: apunte «5. Autómatas reconocedores de Lenguaje», págs. 1 y 2.

    Hay dos clases.

    AFN (no determinista)AFD (determinista)
    Estados a la vezPuede estar en variosSiempre en uno
    Para un estado y un símboloPuede haber más de una transiciónA lo sumo una
    Transiciones εAdmiteNo admite
    TamañoMenos estadosPor lo general más estados (desventaja)
    VelocidadLlega a la respuesta con menos operaciones, es más rápido (ventaja)

    Para un mismo lenguaje regular puede haber un reconocedor AFN y otro AFD. Fuente: apunte «5. Autómatas…», págs. 2 a 5.

    Definición formal de AFN

    Un AFN es un modelo matemático formado por:

    1. Un conjunto finito de «estados» S.
    2. Un alfabeto de «símbolos de entrada» V.
    3. Un estado S₀ que se considera «de inicio» o «inicial» (S₀ ϵ S).
    4. Un conjunto de estados F considerados «estados de aceptación» o «finales» (F ⊆ S).
    5. Una función de transición mueve que transforma pares estado-símbolo en conjuntos de estados. «mueve» es una función que toma como argumentos un estado de S y un símbolo de entrada de V y devuelve un subconjunto de S. mueve : S x V → P(S) conjunto de estados.

    Es decir, un AFN se puede denotar con la quíntupla: AFN = {S, V, S₀, mueve, F}.

    Aceptación de una cadena por parte de un AFN

    Se dice que un AFN acepta una cadena de entrada x si hay algún «camino» en el grafo de transiciones desde el estado de inicio a algún estado de aceptación, tal que concatenando las etiquetas de las sucesivas aristas a lo largo del «camino» se obtiene x (la cadena x).

    Apunte «5. Autómatas…», pág. 4

    El AFN del apunte

    Con estados 0, 1, 2, 3, alfabeto { a, b }, estado inicial 0 y estados finales { 3 }. La tabla es: desde 0 con a va a {0, 1} y con b va a {0}; desde 1 con b va a {2}; desde 2 con b va a {3}; el resto es ∅. Para x = aabb, el camino 0 a 0 a 1 b 2 b 3 llega a aceptación, así que la cadena es aceptada. Para x = aba, ningún intento llega a aceptación, así que la cadena no es aceptada.

    Definición formal de AFD

    Un AFD es un caso especial de un AFN en el cual: 1) ∄ transiciones ε; 2) para cada estado S y cada símbolo de entrada a, hay a lo sumo una arista etiquetada con a saliente del estado S.

    Un AFD es un modelo matemático formado por:

    1. Un conjunto finito de «estados» S.
    2. Un alfabeto de «símbolos de entrada» V.
    3. Un estado S₀ que se considera «de inicio» o «inicial» (S₀ ϵ S).
    4. Un conjunto de estados F considerados «estados de aceptación» o «finales» (F ⊆ S).
    5. Una función de transición «mueve» que toma como argumentos un estado de S y un símbolo de entrada de V y devuelve un estado de S. mueve : S x V → P(S) conjunto de estados.

    Es decir, un AFD se puede denotar con la quíntupla: A = {S, V, S₀, mueve, F}.

    Apunte «5. Autómatas…», pág. 5

    Una línea del apunte que no cierra

    En la definición de AFD el punto 5 dice que mueve devuelve «un estado de S», pero la línea siguiente repite S x V → P(S) del AFN. La transcribí como está. Guiate por el texto del punto 5 y por la observación que sigue en el apunte, «para cada estado y para cada símbolo existe una única alternativa».

    Tabla y grafo de transiciones

    • Tabla de transiciones. Una fila por estado y una columna por símbolo. En un AFN, cada celda es un conjunto, vacío (∅) si no hay transición.
    • Grafo de transiciones. Los nodos son estados y las aristas con etiqueta representan mueve. Pueden llevar ε.

    Una cadena se acepta en un AFN si hay algún camino desde el inicio a un estado final cuyas etiquetas, concatenadas, dan la cadena. Hay que probar todos los caminos. Si ninguno llega, no se acepta.

    En un AFD hay tres resultados: aceptada (termina en estado final), no aceptada (termina en uno no final) o abortada (no hay arista para seguir). La tabla llena es la que no tiene vacíos. En ese caso ninguna cadena aborta. Se puede completar una tabla agregando un estado inactivo.

    Simulación de un AFD en la computadora

    El apunte da el algoritmo para que un programa haga de AFD. Se parte de la tabla de transiciones completa. sgtecar() devuelve el siguiente carácter de la entrada y mueve(S, c) devuelve el estado al que se pasa desde S con el carácter c, leído de la tabla. S0 es el estado inicial y F el conjunto de estados finales.

    S ← S0
c ← sgtecar()
mientras c ≠ eof
    S ← mueve(S, c)
    c ← sgtecar()
si S está en F
    retornar 1   (cadena aceptada)
si no
    retornar 0   (cadena no aceptada)

    El ejemplo del apunte es el AFD de (a|b)*abb. Con la tabla llena, cada carácter tiene una transición y la cadena nunca aborta. Lo que decide es en qué estado termina.

    Método de Thompson: expresión regular a AFN

    Construcción o Método de Thompson

    Para el pasaje de una expresión regular a un AFN se utiliza un método llamado Construcción o Método de Thompson, este método tiene 3 reglas y tiene carácter recursivo. Se construye un AFN para cada uno de los símbolos básicos de la expresión regular r (ε y símbolos del alfabeto). Luego, guiándose por la estructura sintáctica de r, se combinan inductivamente los AFN hasta obtener el AFN de la expresión completa.

    1. Para cada ocurrencia de ε en r, construir el AFN que reconoce el lenguaje { ε }: i y f unidos por una arista ε.
    2. Si a en V, por cada ocurrencia de a en r construir el AFN que reconoce { a }: i y f unidos por una arista a.
    3. Si N ( s ) y N ( t ) son los AFN correspondientes a las e.r. s y t, entonces:
      • 3.a) Para la e.r. s | t, construir el AFN que reconozca la unión de los dos lenguajes. Se colocan en paralelo los 2 AFN y se conectan con ε. Los estados de inicio y aceptación de cada uno dejan de serlo; hay una transición ε desde el nuevo i a los estados de inicio de N(s) y N(t) y hay una transición ε desde los estados de aceptación de N(s) y N(t) al nuevo estado de aceptación f. Todos los caminos desde i a f deben pasar exclusivamente por N(s) o por N(t).
      • 3.b) Para la e.r. s.t, construir el AFN compuesto N ( s . t ). Se colocan en serie los dos AFN y el estado de inicio de N(s) se convierte en el estado de inicio del AFN compuesto. El estado de aceptación de N(t) se convierte en el estado de aceptación del AFN compuesto. El estado de aceptación de N(s) se fusiona con el estado de inicio de N(t). Un camino desde i a f debe pasar primero a través de N(s) y después por N(t).
      • 3.c) Para la e.r. s*, construir el AFN compuesto N ( s )*. i es un nuevo estado de inicio y f un nuevo estado aceptación. Se puede ir desde i a f directamente, a lo largo de una arista etiquetada con ε (ε ∈ (L(s))*), o se puede ir desde i a f por N(s) una o más veces.
      • 3.d) Para la expresión regular ( s ), construir el AFN N ( s ).

    Cada vez que se construye un nuevo estado se le debe dar un nombre distinto.

    Subconjuntos: AFN a AFD

    Cada estado del AFD representa un conjunto de estados del AFN. El AFD simula en paralelo todos los caminos que el AFN podría recorrer. Se usan tres operaciones:

    • cerradura-ε(s): los estados alcanzables desde s solo por transiciones ε.
    • cerradura-ε(T): los alcanzables desde algún estado de T solo por ε, incluidos los propios estados de T.
    • mueve(T, a): los estados alcanzables con una única transición a desde algún estado de T.

    El procedimiento: el estado inicial del AFD es cerradura-ε(s₀). Para cada conjunto no analizado y cada símbolo a se calcula cerradura-ε(mueve(T, a)), y si es un conjunto nuevo se agrega a la tabla. Se repite hasta que no aparecen conjuntos nuevos. Un conjunto es estado de aceptación si contiene al menos un estado de aceptación del AFN.

    Ejemplo del apunte con (a|b)*abb y los estados 0 a 10: cerradura-ε(0) = {0,1,2,4,7} = A; mueve(A, a) = {3,8}, cuya cerradura es {1,2,3,4,6,7,8} = B. El proceso da cinco conjuntos, de A a E, y E contiene al 10, así que es el estado de aceptación. Fuente: apunte «5. Autómatas…», págs. 10 a 13.

    Minimización: el AFD óptimo

    Se parte de la tabla completa. Se agrupan los estados que ninguna cadena puede distinguir y se deja uno por grupo.

    1. Partición inicial π: dos grupos, los estados de aceptación y los de no aceptación.
    2. Se divide cada grupo en subgrupos: dos estados quedan juntos si, para todo símbolo, van a estados del mismo grupo de π.
    3. Si la nueva partición es igual a π, terminó. Si no, se repite el paso 2.
    4. Se elige un representante por grupo. El del inicial es el inicial, y los de los grupos finales son los finales.
    5. Se elimina el estado inactivo (no final y que solo se va a sí mismo) y los estados inalcanzables.

    Ejemplo del apunte con el AFD de (a|b)*abb: la partición inicial es (E) y (ABCD). Se llega a (AC)(B)(D)(E), por lo que A y C son equivalentes y queda un autómata de cuatro estados. Fuente: apunte «5. Autómatas…», págs. 13 a 16.

    Autómatas de pila y de Turing

    Estos autómatas reconocen lenguajes que un AF no puede. El problema típico es aⁿbⁿ: un AF no puede contar cuántas a leyó para compararlas con las b. Un autómata de pila tiene memoria ilimitada para eso.

    Autómata de pila (push-down, APD)

    Es un AF con una pila (stack) agregada. La pila es LIFO: último en entrar, primero en salir. Solo se puede apilar (PUSH) y desapilar (POP).

    Pensá en una pila de platos. Solo ves el de arriba. Para leer el tercero tenés que sacar los dos de arriba, y ya no vuelven.

    Autómata Push-Down

    Un Autómata Push-Down (APD) es una colección de 8 cosas:

    1. Un alfabeto Σ de letras de entrada.
    2. Una CINTA de entrada (infinita en una dirección). Inicialmente la cadena de letras de entrada se ubica en la CINTA comenzando en la celda i. El resto de la CINTA tiene blancos.
    3. Un alfabeto Γ de caracteres del STACK.
    4. Un STACK pushdown (infinito en una dirección). Inicialmente el STACK está vacío (contiene todos blancos).
    5. Un estado START que contiene solo aristas de salida, no aristas de entrada.
    6. Estados de Detención de dos clases: algunos ACCEPT y algunos REJECT. Tienen aristas de entrada y no aristas de salida.
    7. Un número finito de estados PUSH sin ramificación que introducen caracteres en la parte superior del STACK.
    8. Un número finito de estados con ramificación de dos clases: i) estados que leen la próxima letra no usada de la CINTA (READ), que pueden tener aristas de salida etiquetadas con letras de Σ y el carácter blanco ∆, sin restricciones de duplicación de etiquetas y sin obligación de que haya una etiqueta para cada letra de Σ, o una ∆; y ii) estados que leen el carácter superior del STACK (POP), que pueden tener aristas de salida etiquetadas con las letras de Γ y el carácter blanco ∆, nuevamente sin restricciones.

    Apunte «6. PushDown y Turing», págs. 16 y 17

    Cadena aceptada por un APD

    Una cadena de entrada con un camino que termina en un estado ACCEPT se dice que es aceptada. Una cadena de entrada que sigue una lista de caminos se dice que es aceptada si al menos uno de esos caminos llega a un estado ACCEPT. El conjunto de todas las cadenas aceptadas por un APD se llama el Lenguaje Aceptado por el APD o el Lenguaje Reconocido por el APD.

    APD determinista y no determinista

    Máquina de Turing (MT)

    Reconoce los lenguajes de las gramáticas tipo 0.

    Máquina de Turing

    Una Máquina de Turing, denotada MT, es una colección de seis cosas:

    1. Un alfabeto Σ (sigma) de letras de entrada, que por cuestión de claridad no contiene el símbolo blanco ∆.
    2. Una CINTA dividida en una secuencia de celdas numeradas cada una conteniendo un carácter o un blanco. La palabra de entrada se presenta a la máquina una letra por celda comenzando por la celda de más a la izquierda, llamada celda i. El resto de la CINTA se completa inicialmente con blancos ∆.
    3. Una CABEZA de CINTA que puede en un paso leer el contenido de una celda de la CINTA, reemplazarlo con algún otro carácter, y reposicionarse en la próxima celda a la derecha o a la izquierda de aquel que ha sido recién leído. Al principio del proceso, la CABEZA de CINTA siempre empieza leyendo la entrada de la celda i. La CABEZA de CINTA nunca puede moverse hacia la izquierda de la celda i. Si se le dan órdenes de hacerlo, la máquina falla.
    4. Un alfabeto Γ (gamma), de caracteres que pueden ser impresos en la CINTA por la CABEZA de CINTA. Estos pueden incluir Σ. Aún cuando permitamos a la CABEZA de CINTA imprimir un ∆ llamamos a esto borrar y no incluir el blanco como una letra del alfabeto Γ.
    5. Un conjunto finito de estados que incluye exactamente un estado START desde el cual comienza la ejecución (y en el que podemos reingresar durante la ejecución) y algunos (quizá ninguno) estados de HALT que causan que la ejecución termine cuando se ingresa en ellos. Los otros estados no tienen funciones, solo nombres: 1, 2, 3, …
    6. Un programa, que es un conjunto de reglas que nos dicen, en base a la letra que la CABEZA de CINTA ha leído, como cambiar de estado, que imprimir, donde mover la CABEZA de CINTA. Cada arista está etiquetada con un triplete de información: (letra, letra, dirección). La primera letra es el carácter que la CABEZA de CINTA lee. La segunda letra es lo que imprime en la celda antes de dejarla. La dirección le dice si moverse una celda a la derecha, R, o una celda a la izquierda, L.

    Para terminar la ejecución de una entrada exitosamente debemos llegar a un estado de HALT. La palabra en la CINTA de entrada se dice que es aceptada por la MT. Por definición todas las máquinas de Turing son deterministas. Esto significa que no hay un estado q que tenga dos o mas aristas que salen de él etiquetadas con la misma primera letra.

    Autómata linealmente acotado

    C: punteros

    Un puntero es una variable que contiene una dirección de memoria, normalmente la de otra variable.

    int x, *p;    /* p es un puntero a int */
p = &x;       /* & devuelve la dirección de x */
*p = 3;       /* * accede al contenido apuntado: x vale 3 */
    • & es el operador de dirección. * es el de indirección, que da el contenido.
    • Con %p en printf se muestra la dirección.
    • Antes de usar un puntero hay que asignarle una dirección. Si no, apunta a cualquier lado. Un puntero que no apunta a nada se inicializa con NULL y nunca se desreferencia.
    • Aritmética. Solo se puede sumar o restar un entero a un puntero. Al sumar 1, el puntero avanza un elemento de su tipo base, no un byte.
    • Arreglos y punteros. El nombre de un arreglo es la dirección de su primer elemento. a[i] equivale a *(a + i). Un puntero es una variable y se puede hacer p++. Un arreglo no, y a++ o a = p son ilegales.
    • Punteros a estructuras. Se accede con el operador ->: ap->x.

    Fuente: apunte «Lenguaje C», págs. 47 a 55 y 58.

    Arreglos bidimensionales y punteros

    Un arreglo de dos dimensiones es un arreglo de una dimensión en el que cada elemento es a su vez un arreglo. Se guarda renglón por renglón.

    Cuando se pasa un arreglo bidimensional a una función hay que dar el número de columnas. El de renglones es irrelevante. C necesita saber cuántas columnas hay para saltar de renglón en renglón en la memoria. Para recibir int a[5][35] el apunte da dos formas.

    f(int a[][35]) { ... }
f(int (*a)[35]) { ... }   /* los paréntesis hacen falta: [ ] tiene más precedencia que * */

    int (*a)[35] es un puntero a un arreglo de 35 enteros. int *a[35] es otra cosa, un arreglo de 35 punteros a enteros.

    Con cadenas pasa lo mismo. char anomb[10][20] es un arreglo verdadero de 200 char, y el elemento anomb[r][c] está en 20*r + c desde la base. char *nomb[10] son 10 punteros, y cada uno puede apuntar a una cadena de distinto largo. En los dos vale escribir [3][4]. El apunte remarca que el arreglo de punteros maneja el espacio de forma más eficiente.

    char *nomb[] = { "No mes", "Ene", "Feb", "Mar" };
char anomb[][15] = { "No mes", "Ene", "Feb", "Mar" };

    Fuente: apunte «Lenguaje C», págs. 53 y 54.

    Usar un puntero sin asignarle memoria (int *x; *x = 100;) y escribir *p = (char *) malloc(100) cuando debía ser p = (char *) malloc(100). En el segundo, malloc devuelve un puntero y el * lo trata como si ya apuntara a algo.

    Fuente: apunte «Lenguaje C», pág. 55 (sección «Fallas comunes con punteros»).

    C: funciones

    Una función tiene prototipo (tipo devuelto, nombre y tipos de parámetros, sin cuerpo), definición y llamada. Se escribe el prototipo antes del main para que el compilador conozca la función.

    Lo que el apunte remarca de cada parte.

    • Prototipo. Su forma es tipo_de_retorno nombre_función(lista_de_parámetros);. Le dice al compilador el nombre, el tipo que devuelve y el número y tipo de los argumentos, para que chequee si lo que se envía y lo que se devuelve se corresponde. Los tipos del prototipo y de la declaración de la función deben coincidir.
    • Tipo de retorno. Si la función no devuelve nada va void. Si no se indica ninguno, se asume int.
    • Parámetros. En la definición se llaman parámetros formales y en la llamada, argumentos actuales o reales. Cada formal debe tener el mismo tipo que el actual que le corresponde. Los formales son variables locales que reciben un valor. Si la función no recibe nada, se pone void.
    • main. La ejecución siempre empieza por main. Las funciones se llaman desde main o desde otras funciones, pero nunca se llama a main desde otro lugar del programa.

    Fuente: apunte «Lenguaje C», págs. 66 a 69.

    return y void

    return devuelve información al punto de llamada. Su forma es return ( valor o expresión );. Una función puede tener más de un return, pero cada uno devuelve un solo valor. Para devolver más de uno hace falta otro mecanismo, como el paso por referencia. Si no asignás a una variable el valor devuelto, se pierde.

    La expresión es opcional. Sin ella, return solo devuelve el control. Una función void no devuelve valor.

    Fuente: apunte «Lenguaje C», págs. 13 y 69.

    Tres reglas del apunte:

    • Un arreglo siempre se pasa por referencia, porque su nombre es la dirección del primer elemento.
    • Una estructura se puede pasar por valor (las modificaciones son locales) o por referencia (son permanentes).
    • Una variable local existe mientras dura la función. Con static, conserva su valor entre llamadas, se reserva en forma permanente y se inicializa en 0.
