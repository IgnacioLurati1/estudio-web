    Un módulo es un archivo Python y se importa con su nombre, sin la extensión. Al ejecutarlo directamente, __name__ vale "__main__". Al importarlo, vale el nombre del módulo (Python para todos, págs. 72 a 76).

    La aplicación mínima de Flask

    Flask es un framework web en Python, basado en el toolkit WSGI Werkzeug y el motor de plantillas Jinja2 (Flask Tutorial, pág. 1).

    from flask import Flask
app = Flask(__name__)

@app.route('/')
def hello_world():
    return 'Hello World'

if __name__ == '__main__':
    app.run()

    Un objeto de la clase Flask es la aplicación WSGI. Su constructor recibe el nombre del módulo actual. route es un decorador que indica qué URL llama a la función. run arranca el servidor local (pág. 3). El objeto request también hay que importarlo. Sus atributos son form, args, cookies, files y method (pág. 18).

    sqlite3

    Python trae su propio módulo para SQLite. No hace falta un servidor aparte (Foundations for Analytics, capítulo 4, págs. 145 y 148). connect recibe la ruta del archivo, o ':memory:' para usar la RAM. Si el archivo no existe, se crea (Python para todos, pág. 120, y Python para informáticos, pág. 177).

    import sqlite3
conn = sqlite3.connect('musica.sqlite3')
cur = conn.cursor()
cur.execute('DROP TABLE IF EXISTS Canciones ')
cur.execute('CREATE TABLE Canciones (titulo TEXT, reproducciones INTEGER)')
conn.close()
    MétodoDevuelve
    fetchone()La siguiente tupla, o None si no hay más
    fetchmany(n)La cantidad de tuplas indicada
    fetchall()Todas las tuplas

    Cada fila es una tupla, y fetchall da la lista de esas tuplas (Python para todos, pág. 122, y Foundations, pág. 150). Cada cambio se confirma con commit(). Si no lo llamás, no se guarda (Foundations, pág. 148).

    Este es el ejemplo completo del tutorial de Flask para listar registros, la misma combinación que tomó el parcial (págs. 52 y 53).

    from flask import Flask, render_template, request
import sqlite3 as sql
app = Flask(__name__)

@app.route('/list')
def list():
    con = sql.connect("database.db")
    con.row_factory = sql.Row
    cur = con.cursor()
    cur.execute("select * from students")
    rows = cur.fetchall()
    return render_template("list.html", rows=rows)

if __name__ == '__main__':
    app.run(debug=True)

    El SQL que hace falta

    Sale de Python para informáticos, capítulo 14, págs. 180 y 181.

    CREATE TABLE Canciones (titulo TEXT, reproducciones INTEGER)
INSERT INTO Canciones (titulo, reproducciones) VALUES ('My Way', 15)
SELECT * FROM Canciones WHERE titulo = 'My Way'
SELECT titulo, reproducciones FROM Canciones ORDER BY titulo
UPDATE Canciones SET reproducciones = 16 WHERE titulo = 'My Way'
DELETE FROM Canciones WHERE titulo = 'My Way'
    • El * pide todas las columnas. WHERE elige las filas.
    • En SQL la igualdad es con un solo =, a diferencia de Python.
    • Un UPDATE sin WHERE actualiza todas las filas de la tabla.

    No armes el SQL pegando cadenas. Te deja vulnerable a la inyección SQL. Los ? marcan dónde van los valores y se pasan aparte, en una tupla (Python para todos, pág. 123).

    Sale de apuntes de alumnos

    No es de la cátedra. Es lo único que hay para el quiz de ese tema.

    Business Intelligence. Software que se alimenta de datos de negocios y presenta reportes, paneles, tablas y gráficos para facilitar la toma de decisiones. No les dice a los usuarios qué hacer ni se trata solo de generar informes. Las herramientas ETL, o ETC en castellano (extracción, transformación y carga), sacan datos de distintas fuentes, los preparan y los cargan en un almacén de datos.

    Las funciones principales de Power BI son conexión, transformación y modelado de datos, creación de informes, paneles de control, y colaboración.

    ElementoQué es, según el seminario
    Conjunto de datosLa colección de datos que usa para sus visualizaciones. Puede combinar muchos orígenes
    TooltipMensaje emergente con información adicional sobre lo que muestra una visualización. No todas lo tienen

    TPI

    Hay que hacer un sistema programado en Python que cumpla la arquitectura de capas. Grupos de 3 a 4 integrantes, con un repositorio en GitHub que suma como colaboradores a la cátedra, y la norma de programación PEP 8.

    CapaCondiciones de la cátedra
    DatosUsa una base de datos (MySQL, Mongo o SQLite), con acceso directo o por un ORM (Alchemy, Django). Lleva la documentación del modelo del dominio
    NegocioEvalúa por lo menos una regla de negocio. Lleva un test que evalúa que se cumplan esas reglas en los métodos de la clase de negocio
    Interfaz de usuarioPuede ser de escritorio (Tkinter), web (Flask, Django, Kivy) o una API

    La documentación se imprime por duplicado, con carátula con los integrantes y el tema del trabajo. Debe contener carátula (materia, número de grupo, integrantes y tema), narrativa, abstract, requerimientos funcionales, requerimientos no funcionales, stack tecnológico, reglas de negocio, casos de uso principales, modelo de dominio, imágenes de la interfaz, referencia bibliográfica y link al código fuente y al documento.

    La consigna escribe «Requerimientos No funcionales 2». No queda claro si pide dos. Consultalo.

    La consigna también recomienda, sin exigirlo, que se relacione con el tema del seminario, que les resulte interesante, que consulte alguna API y que genere algún resultado visible. Ya se presentaron ecommerce, red social, sistema de turnos, de pedidos, de inventario y de cine.

    La capa de datos con SQLAlchemy

    Si usás el ORM, estos son los pasos de las diapositivas de la cátedra (introduccion a python2018_sqlAlchemy.pptx).

    1. Declarar el mapeo de la base de datos, lo que crea los metadatos.
    2. Crear clases para cada entidad.
    3. Crear el Engine para un motor de base de datos.
    4. Relacionar el Engine con los metadatos.
    5. Crear la Session y relacionarla con el Engine.
    6. Usar la sesión para gestionar los datos.
    from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy import Column, ForeignKey, Integer, String, create_engine
from sqlalchemy.orm import relationship, sessionmaker

Base = declarative_base()

class Persona(Base):
    __tablename__ = 'persona'
    id = Column(Integer, primary_key=True)
    nombre = Column(String(250), nullable=False)

engine = create_engine('sqlite:///sqlalchemy_ejemplo.db')
Base.metadata.create_all(engine)     # equivale a Create Table en SQL

Base.metadata.bind = engine
DBSession = sessionmaker()
DBSession.bind = engine
session = DBSession()

oper = Persona()
oper.nombre = 'Juan Carlos'
session.add(oper)
session.commit()     # graba

lp = session.query(Persona).all()

    La diapositiva da como actual la versión 1.2.7, así que algunas importaciones pueden diferir en una versión nueva.
