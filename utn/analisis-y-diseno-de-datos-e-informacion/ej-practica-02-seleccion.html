    Uso la notación de la clase 1. e: marca un flujo de entrada y s: uno de salida, (e) una estructura, y después del ; van el tipo y los valores de un elemento discreto. Sigo el orden de la narrativa.

    1. Ingreso y usuario nuevo.

    e: nuevoUsuario = usuario + contraseña
e: ingreso = usuario + contraseña
s: resultadoIngreso = mensajeIngreso
mensajeIngreso = ["Usuario o contraseña incorrectos" | "El usuario ya existe"]

    2. Formulario web y actualización. Al registrar, el sistema activa a la persona para las búsquedas, que es una respuesta interna.

    e: formularioPostulante = datosPersonales(e) + 0{estudio(e)}n + 0{antecedenteLaboral(e)}n
datosPersonales(e) = apellido + nombres + tipoDoc + nroDoc + fechaNacimiento + sexo + domicilio + teléfono + mail
estudio(e) = nivelEstudio + estadoEstudio + (título)
antecedenteLaboral(e) = empresa(e) + cargo + fechaInicio + (fechaFin)
empresa(e) = cuit + (razónSocial)
nivelEstudio = char(13); [primario | secundario | terciario | universitario]
estadoEstudio = char(10); [completo | incompleto]
sexo = char(9); [femenino | masculino]

e: actualizaciónPostulante = (datosPersonales(e)) + 0{estudio(e)}n + 0{antecedenteLaboral(e)}n + (estadoBúsqueda)
estadoBúsqueda = char(8); [activo | inactivo]
    • Cualquier combinación de estudios entra con 0{estudio(e)}n, cada uno con su nivel y si está completo o no.
    • razónSocial va entre paréntesis y se pide solo si el CUIT no está en los registros de la agencia.
    • fechaNacimiento y sexo están porque las empresas filtran por edad y a veces por sexo. Según la clase 2, cada dato que usa el sistema para responder tiene que haber entrado o estar en una clase del modelo. Los dos valores de sexo siguen el gráfico de la clase 3, que lo trata como un discreto de dos valores.
    • fechaFin es opcional, porque si la persona trabaja ahí todavía no la tiene. Eso dice si «actualmente tiene empleo».

    3. Pedido de la empresa e informe de candidatos.

    e: pedidoPersonal = cuitEmpresa + 1{cargoSolicitado(e)}n
cargoSolicitado(e) = cargo + estudioRequerido(e) + añosExperiencia + edadMínima + edadMáxima + (sexo)
estudioRequerido(e) = nivelEstudio + estadoEstudio

s: informeCandidatos = 1{cargo + [1{candidato(e)}n | mensajeSinCandidatos]}n
candidato(e) = datosPersonales(e) + 0{estudio(e)}n + 0{antecedenteLaboral(e)}n
mensajeSinCandidatos = "No hay candidatos disponibles para el cargo"

    El corchete de la salida es la misma forma del CUU01 de la cátedra, [mensaje | 1{hora turno}n]. Cada cargo trae sus candidatos o el aviso de que no hay.

    4. Contratación.

    e: contratación = cuitEmpresa + 1{contratoPersona(e)}n
contratoPersona(e) = nroDoc + cargo + fechaInicioContrato + fechaFinContrato + montoContrato

    5. Contratos que vencen en 15 días. El pedido de la gerencia no trae datos, el sistema toma la fecha del día.

    s: informeVencimientos = fechaEmisión + 0{empresaContacto(e) + 1{contratoPorVencer(e)}n}n
empresaContacto(e) = cuit + razónSocial + teléfonoEmpresa + mailEmpresa
contratoPorVencer(e) = apellido + nombres + cargo + fechaInicioContrato + fechaFinContrato

    6. Informe mensual de comisiones. Va a cada empresa que contrató en el mes, con copia a la gerencia.

    s: informeComisiones = mesAño + empresa(e) + 1{contratado(e)}n + importeTotalComisión + fechaVencimientoComisión
contratado(e) = apellido + nombres + nroDoc + cargo + fechaInicioContrato + montoContrato + porcentajeComisión + importeComisión
    • importeComisión es el porcentaje por el monto del contrato. fechaVencimientoComisión es el fin del primer mes del contrato.
    • Para que la comisión se pueda calcular, el monto tiene que haber entrado. Por eso sumé montoContrato a la contratación, aunque la narrativa no lo nombra ahí.
