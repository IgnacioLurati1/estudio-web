    Teoría

    Pautas de accesibilidad. La WAI, Iniciativa de Accesibilidad Web, es una actividad del W3C. Las WCAG, Pautas de Accesibilidad al Contenido en la Web, son su documento más importante. Las 12 pautas de WCAG 2.0 se agrupan en 4 principios.

    1. Perceptibilidad: alternativas textuales, alternativas para multimedia, contenido adaptable y hacer más fácil ver y oír.
    2. Operabilidad: disponible por teclado, tiempo suficiente, no causar ataques y ayudar a navegar.
    3. Comprensibilidad: legible, predecible y ayudar a evitar y corregir errores.
    4. Robustez: compatibilidad con agentes de usuario actuales y futuros.

    WCAG 2.0 tiene 4 principios, 12 directrices y 61 criterios de cumplimiento. La versión anterior, WCAG 1.0, tiene 14 pautas con puntos de prioridad. La prioridad 1 el desarrollador tiene que cumplirla, porque si no ciertos grupos no podrían acceder. La 2 y la 3 debería cumplirlas. El nivel de conformidad A satisface la prioridad 1, el doble A las prioridades 1 y 2, y el triple A las tres.

    Estructura y diseño. La estructura es la forma que tendrá el sitio en términos generales, con sus secciones, funcionalidades y sistemas de navegación. No incluye elementos gráficos. El diseño es la solución gráfica, con colores, logotipos, viñetas y otros elementos que identifican visualmente al sitio.

    Arquitectura de la información. Es el conjunto de métodos y herramientas que permiten organizar los contenidos, para ser encontrados y utilizados por los usuarios, de manera simple y directa. Sus elementos son objetivos, audiencia, contenidos, estructura y diseño visual.

    Interfaz. Es el conjunto de elementos de la pantalla que permiten al usuario realizar acciones sobre el sitio web que está visitando. Hay elementos de identificación, de navegación, de contenidos y de acción.

    Práctica

    Un formulario con estilos en hoja externa, validado en el navegador y en el servidor, que guarda el nombre en una cookie y cuenta los envíos en la sesión. La validación del servidor es una función de 3 parámetros.

    form.html. required controla los vacíos, y type="number" y type="email" controlan el tipo de dato.

    <!DOCTYPE HTML>
<html>
<head>
<title>Inscripción</title>
<meta charset="UTF-8">
<link rel="stylesheet" href="estilos.css" type="text/css">
</head>
<body>
<h1>Inscripción</h1>
<form action="procesar.php" method="post">
<label for="nombre">Nombre:</label>
<input type="text" id="nombre" name="nombre" required><br>
<label for="edad">Edad:</label>
<input type="number" id="edad" name="edad" min="1" max="120" required><br>
<label for="email">Email:</label>
<input type="email" id="email" name="email" required><br>
<input type="submit" value="Enviar">
</form>
</body>
</html>

    procesar.php. validarDato recibe el valor, el tipo que se espera y si es obligatorio. El tercero tiene valor por defecto, así que va a la derecha de los otros dos. Los tres van por valor. isset con varios parámetros da TRUE solo si llegaron todos. session_start() y setcookie van antes de escribir texto.

    <?php
session_start();

function validarDato($valor, $tipo, $obligatorio = true)
{
  if (trim($valor) == "") {
    return !$obligatorio;
  }
  if ($tipo == "numero") {
    return ctype_digit($valor);
  }
  if ($tipo == "email") {
    return filter_var($valor, FILTER_VALIDATE_EMAIL) !== false;
  }
  return true;
}

$vValido = false;
if (isset($_POST['nombre'], $_POST['edad'], $_POST['email'])) {
  $vNombre = $_POST['nombre'];
  $vValido = validarDato($vNombre, "texto") && validarDato($_POST['edad'], "numero") && validarDato($_POST['email'], "email");
}
if ($vValido) {
  setcookie("nombre", $vNombre, time()+86400*30);
  if (!isset($_SESSION["envios"])) {
    $_SESSION["envios"] = 1;
  } else {
    $_SESSION["envios"]++;
  }
}
?>
<!DOCTYPE HTML>
<html>
<head>
<title>Inscripción</title>
<meta charset="UTF-8">
<link rel="stylesheet" href="estilos.css" type="text/css">
</head>
<body>
<?php
if (!$vValido) {
  echo "<p>Hay campos vacíos o con un tipo de dato incorrecto.</p>";
} else {
  if (isset($_COOKIE["nombre"])) {

    La cookie que se crea en un envío recién se lee en $_COOKIE en el siguiente, porque viaja con el próximo pedido del navegador.
