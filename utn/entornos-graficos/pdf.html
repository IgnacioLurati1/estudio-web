Para entender

Cómo se planifica, se arma y se pone a andar un sitio web, y cómo se hace para que cualquiera pueda usarlo.

Resumen no juzgado. Todavía nadie evaluó si alcanza para estudiar solo con esto.

De qué se trata

La materia sigue la vida de un sitio web. Primero se decide para qué sirve y a quién le habla. Después se arma la página con HTML y se le da aspecto con CSS. Con PHP y MySQL deja de ser una hoja fija. Recibe datos, los guarda y recuerda a quien entra. Al final se revisa que lo pueda usar cualquier persona, también con una discapacidad o con otro idioma.

Por eso se rinde con dos cabezas distintas. Una parte es escribir código que funcione en la máquina. La otra es teoría de definiciones, pautas y etapas de diseño.

Cómo se conecta

Cada tema resuelve un problema que deja el anterior.

  • El HTML ordena el contenido, pero no decide cómo se ve. De eso se ocupa el CSS.
  • Un formulario junta datos, pero HTML no los procesa. Los recibe PHP.
  • PHP olvida todo cuando termina la página. Para que dure hay tres lugares: la base de datos, la sesión en el servidor y la cookie en el navegador.
  • Un sitio que anda puede ser imposible de usar. Ahí entran la usabilidad y la accesibilidad.

Esa cadena es la misma que piden los exámenes de práctica de 2024: página con estilos, formulario, PHP que guarda, sesión y cookie.

Anatomía de una regla

h1 {color: red;}

Una regla tiene un selector y una declaración. La declaración es una propiedad con un valor. El selector es el enlace entre el documento y el estilo (Material de CSS, página 4). Varias declaraciones entre llaves forman un bloque (Contenido adicional de CSS, página 5).

Se agrupan selectores con coma: h1, h2, h3 { color: red; }. Los comentarios van con /* */ (Material de CSS, páginas 9 y 12).

Otras reglas de sintaxis del mismo apunte.

  • Las declaraciones se separan con punto y coma, y la última también lo lleva (páginas 9 y 16).
  • Si una propiedad lleva varios valores, van separados por espacios. Si admite valores alternativos, van separados por comas, como font-family: Georgia, "Times New Roman", Times, serif; (página 9).
  • Un valor de más de una palabra va entre comillas, como p {font-family: "sans serif";} (página 10).
  • Un error habitual es escribir los caracteres < y > en la hoja de estilo (página 10).
  • No se aconseja repetir selectores, porque dispersa la información (página 11).
  • Las reglas-arroba empiezan con @. @charset, @import y @namespace van al principio de la hoja. @font-face y @media pueden ir en cualquier lugar (página 8).
  • El meta charset va justo después de abrir head, para que el navegador conozca la codificación antes de procesar nada (página 3).

En cuanto a unidades, el punto, pt, es absoluto y no varía según el entorno. El em es relativo al tamaño de la fuente del elemento, así que margin: 3em es tres veces ese tamaño (página 16).

Cascada, herencia y especificidad

Cascada. El formato final de un elemento depende de la combinación de todas las propiedades que lo afectan, también las de los elementos que lo incluyen. Si una propiedad se repite con el mismo peso, gana la última (Material de CSS, páginas 10 y 11).

Herencia. Un p hereda de body (Material de CSS, páginas 14 a 16). Si body tiene color negro y h1 tiene su propio color rojo, la regla de h1 reemplaza el valor heredado. Conviene fijar juntos el color del texto y el del fondo (página 15).

PHP

Tipos

boolean, integer, float, string, array, object, resource y NULL. gettype dice el tipo, e is_int pregunta si es entero (Introducción teórica de PHP, páginas 2 y 15).

Son cuatro escalares, dos compuestos y dos especiales. resource guarda una referencia a un recurso externo, como un archivo o una imagen (página 2).

Una constante guarda un valor que no cambia durante el script. Se define con define o, desde PHP 5.3.0, con const (páginas 3 y 4).

<?php
define ("saluda", "Buenas tardes.");
echo saluda;
const CONSTANT = 'Hola Mundo';
?>

Hay operadores unarios, como ! y ++, binarios, como +, y uno ternario, ?:. El ejemplo del apunte es $a == 1 ? $a++ :$a*3; (página 5).

Funciones y parámetros

Una función agrupa código para ejecutarlo varias veces, o con distintos parámetros. return devuelve el valor al lugar desde donde se la llamó (Introducción teórica de PHP, página 6).

<?php
function prueba($arg1, $arg2) {
echo "Argumento 1 vale: $arg1<br>";
echo "Argumento 2 vale: $arg2<br>";
if ($arg1 < $arg2){
return true;
}
else {
return false;
}
}
$valor_devuelto = prueba(5,10);
?>

Es el ejemplo de las páginas 6 y 7. La sintaxis general, con los parámetros que hagan falta, es function foo ($arg_1, $arg_2, ..., $arg_n) (página 9).

El parámetro va por valor si no se indica otra cosa. Un & lo pasa por referencia, y entonces el cambio afecta a la variable original (páginas 10 a 12).

<?

Un parámetro con valor por defecto se escribe con =, y el valor es una constante. Los que tienen valor por defecto van a la derecha de los que no tienen (páginas 13 y 14).

Conectarse

<?php
$link = mysqli_connect("localhost", "root") or die ("Problemas de conexión a la base de datos");
mysqli_select_db($link, "docentes");
?>

Es conexion.inc del apunte, página 1. Cada página lo incluye con include.

La sintaxis general es $nombreConexion = mysqli_connect($hostname, $nombreUsuario, $contraseña);. El servidor sale de la cuenta de hosting, y el usuario es el de la base, que puede ser root si no se creó otro (Teoría de manejo de bases de datos, páginas 10 y 11).

mysql o mysqli

El material mezcla las dos familias. mysql_connect es para versiones anteriores a PHP 5 y las soluciones viejas la usan. Además el orden de los parámetros cambia. mysqli_select_db($link, "base") y mysqli_query($link, $consulta) llevan la conexión primero. mysql_select_db("base", $link) la lleva al final (Teoría de manejo de bases de datos, páginas 10 a 14).

Sesiones

Una sesión es un conjunto de variables guardadas en el servidor, una por cada visitante (Teoría de Sesiones, página 2). Se usa para mantener datos durante toda la visita.

Aparece en 3 de 4 prácticas de 2023 y 2024.

session_start() inicia o continúa la sesión. Hay que llamarla antes de escribir cualquier texto en la página (Teoría adicional de PHP, páginas 17 y 18). $_SESSION es un array asociativo.

if (!isset($_SESSION["contador"])){
$_SESSION["contador"] = 1;

}
?>

El ejemplo cuenta las páginas visitadas (Teoría adicional, página 19). session_destroy termina la sesión (páginas 23 y 24).

Al llamar a session_start(), PHP recibe el identificador de sesión que viene en la cookie o en la URL, y si no hay ninguno lo crea (página 17). session_destroy() borra la información de la sesión actual, pero no las variables globales asociadas ni la cookie de sesión. Para desconectar del todo al usuario también hay que destruir el id y borrar esa cookie (páginas 23 y 24).

Si no se quiere que session_start() sea la primera línea, ob_start guarda la salida en un búfer y ob_end_flush la envía después. Así se elige cuándo mandar el resultado al navegador (Teoría de Sesiones, páginas 15 y 16).

La Web y HTML

La Web se basa en tres mecanismos: un esquema uniforme de nombres, los URIs; protocolos, como HTTP; e hipertexto, HTML (Conceptos y Teoría de HTML, página 5).

¿Cómo se componen los URIs?Ejemplo de parcial, Tema 1, sin fecha

Normalmente de tres partes:

  1. El esquema de nombres del mecanismo para acceder al recurso.
  2. El nombre de la máquina que aloja el recurso.
  3. El nombre del recurso, dado como una ruta.

Fuente: apunte Conceptos y Teoría de HTML, página 6.

Un URI identifica y un URL localiza. Todo URL es URI, pero hay URI que no son URL (página 8). Un URN, Uniform Resource Name, identifica un recurso por un nombre único. Un URI puede ser un URL, un URN o las dos cosas (página 9).

esquema://máquina/directorio/archivo#fragmento

http://www.w3.org/TR se lee así. Hay un documento disponible por el protocolo HTTP, en la máquina www.w3.org, en la ruta /TR (página 10). El esquema sirve para clasificar. Los más comunes son http, https para páginas seguras, mailto para correo y ftp para transferir archivos (página 11).

HTML es un lenguaje de marcado. Usa etiquetas y no tiene funciones aritméticas ni variables (página 16). El W3C es un consorcio internacional que genera recomendaciones y estándares para la Web (página 4). La World Wide Web es un sistema de distribución de documentos de hipertexto o hipermedia interconectados y accesibles por Internet (página 4).

Según el apunte, HTML da a los autores herramientas para cuatro cosas (página 12).

  • Publicar documentos con encabezados, textos, tablas, listas y fotos.
  • Obtener información por vínculos de hipertexto.
  • Diseñar formularios para transacciones con servicios remotos, como buscar, reservar o pedir productos.
  • Incluir hojas de cálculo, videos, sonidos y otras aplicaciones en el documento.

HTML5 es la quinta revisión importante del lenguaje. Suma audio y video sin Flash ni otros complementos, geolocalización con permiso del usuario, dibujo 2D con canvas y almacenamiento local en el navegador. Entre sus ventajas el apunte cuenta que es gratuito, que ordena el código con etiquetas como header y que se adapta a los navegadores móviles (páginas 15 a 24).

Scripts

Un script es un programa que viaja con la página y corre en la máquina de quien la mira. Por eso puede revisar un formulario antes de enviarlo.

Formalmente, es un programa del lado del cliente que acompaña o está incluido en un documento HTML. Se ejecuta al cargar la página o ante un evento. Hay dos tipos: el que corre una sola vez al cargar, con SCRIPT y NOSCRIPT como alternativa, y el que corre ante un evento, con los atributos de eventos intrínsecos (Material Complementario, página 39).

La misma página da cuatro usos.

  • Modificar el contenido del documento a medida que se carga.
  • Procesar los datos de un formulario mientras se ingresan, por ejemplo controlar que estén en un rango o que los campos sean consistentes entre sí.
  • Responder a eventos como la carga, la descarga, el foco o los movimientos del ratón.
  • Vincularse a controles del formulario, como botones, para armar la interfaz.

Gracias a los scripts se arman páginas dinámicas, como los «formularios inteligentes» que reaccionan mientras el usuario los completa. El soporte de scripts de HTML no depende del lenguaje del script (Material Complementario, páginas 10 y 39).

Arquitectura de la información

Es el conjunto de métodos y herramientas que permiten organizar los contenidos, para ser encontrados y utilizados por los usuarios, de manera simple y directa. Sus elementos son:

  1. Objetivos.
  2. Audiencia.
  3. Contenidos.
  4. Estructura.
  5. Diseño visual.

La audiencia se clasifica por capacidad física, capacidad técnica, conocimiento de la institución, necesidades de información y ubicación geográfica. Los contenidos incluyen servicios interactivos, como contacto, mapa, buscador y área privada (Resumen de la Guía, página 1).

Cada elemento, con lo que agregan los apuntes.

  • Audiencia. Hacia qué públicos se orienta el sitio. Se averigua investigando en la propia institución a quiénes atiende cada repartición, sobre todo entrevistando a quienes atienden al público. Otra forma es estudiar escenarios de uso, situaciones reales de usuarios que llegan a buscar algo. Sistema de navegación

¿Qué es un sistema de navegación, y cuáles son sus características y elementos?Final 15/03/2023

Es el conjunto de elementos presente en cada una de las pantallas que permite a un usuario moverse por el sitio. Tiene que ser consistente, uniforme y visible. Sus elementos son menú general, pie de página, ruta de acceso, fecha de publicación, botón al inicio, mapa del sitio, contacto, buscador, ayuda e imprimir.

Fuente: apunte Resumen de la Guía, página 3, y Adicional guía para desarrollo web, página 60.

Las tres características quieren decir lo siguiente (Resumen de la Guía, página 3).

  • Consistente. Similar en ubicación y disposición en todas las páginas.
  • Uniforme. Usa términos similares, para que el usuario confíe en que sus opciones lo llevan siempre a los mismos lugares.
  • Visible. Se distingue claramente, para que el usuario lo tenga como guía permanente en cualquier parte del sitio.

El mismo resumen insiste en que todas las páginas del sitio tengan el sistema de navegación, y llama a la ruta de acceso «breadcrumbs o rastro» (página 3).

Con los sistemas de navegación los usuarios avanzan por las áreas del sitio sin perderse. Lo textual son elementos concretos, como menús, guías y botones, que se distinguen claramente en la interfaz. Lo contextual usa elementos de texto, gráficos o de entorno, como la gráfica, la redacción de los textos y hasta el nombre del dominio, que le hace sentir al usuario que está en el lugar indicado.

¿Cuál es la diferencia entre buscabilidad y visibilidad?Final 15/03/2023

Las dos son partes de la ubicuidad, que es estar en la Web y poder ser encontrado y visto. La buscabilidad es poder encontrar el sitio. La visibilidad es poder verlo, y depende del desempeño computacional del sitio, de la calidad del enlace a Internet y del diseño.

Fuente: apunte Ubicuidad y Usabilidad en la Web, páginas 3 a 5.

Un sitio se encuentra de tres formas (páginas 2 y 3).

  • Directa. Se conoce la dirección por publicidad o por otra persona. Es cara o lenta.
  • Navegando. Se llega por enlaces desde otros sitios. Es la forma natural, pero favorece a los sitios populares o con más recursos.
  • Con un buscador. El buscador tiene que haber encontrado el sitio antes. Es la más sencilla y casi la única para sitios nuevos o chicos.

Hay un orden causal. Sin encontrar el sitio no se lo puede ver, y sin verlo no se lo puede usar (página 3).

La accesibilidad se centra en eliminar las barreras de diseño que impiden a personas con discapacidad, o con restricciones tecnológicas, acceder, usar y comprender la información (páginas 3 y 4). Las diversidades que hay que tener en cuenta son estas (páginas 5 y 6).

  • Personalidad.
  • Cultura, que afecta cómo se interpretan formatos, medidas, títulos y signos de puntuación.
  • Discapacidades, que son las que contempla la accesibilidad.
  • Edad.
  • Tecnología, como la conexión, el tamaño de pantalla y la memoria.

Accesibilidad

Un sitio es accesible cuando cualquier persona, independientemente de sus capacidades personales o tecnológicas, puede acceder, usarlo y comprenderlo. Incluye discapacidades visuales, auditivas, motoras y cognitivas, y también la edad (Accesibilidad_Usabilidad_RESUMEN, página 2 en adelante).

El acceso universal se entiende independiente de hardware, software, infraestructura de red, idioma, cultura, localización geográfica y capacidades (diapositivas de lectura obligatoria de accesibilidad, página 1).

La introducción de la unidad suma dos definiciones. La accesibilidad universal es el grado en que todas las personas pueden usar un objeto, visitar un lugar o acceder a un servicio, más allá de sus capacidades técnicas, cognitivas o físicas. La e-accesibilidad es el derecho de acceso a la información digital más allá de las singularidades físicas, psíquicas, culturales, geográficas o económicas (Introducción de Accesibilidad, páginas 12 y 13).

Las personas con discapacidad navegan con tecnologías de apoyo. Son dispositivos, equipos, hardware y software que incrementan, mantienen o mejoran sus capacidades funcionales. El apunte muestra la línea braille, el alto contraste, ratones y teclados adaptados, el reconocimiento de voz, un dispositivo para manejar la computadora con la cabeza y un navegador para niños autistas (páginas 3 a 11).

La accesibilidad no es solo para personas con discapacidad. También ayuda con discapacidades temporarias, la edad, la baja alfabetización o poco dominio del idioma, la conectividad limitada o tecnologías viejas, y a los usuarios principiantes (página 16). El apunte la relaciona además con el posicionamiento en buscadores, porque Google solo ve lo que puede ver un ciego, y con el diseño adaptable a celulares (páginas 18 y 19).

Las barreras se agrupan en cuatro tipos. Las tres primeras afectan a cualquier usuario, y solo la cuarta a personas con discapacidad (Accesibilidad un problema pendiente, página 9).

  1. De software o hardware, como un navegador sin el complemento que la página necesita.
  2. De entorno o contexto, como un video en un lugar muy ruidoso.
  3. Del diseño del documento, como una letra muy chica.
  4. Discapacidades, como la ceguera o la sordera.

Para una empresa privada, el mismo texto cuenta seis ventajas. Gana visitantes, mejora la usabilidad, ayuda a extranjeros con poco dominio del idioma, mejora la posición en buscadores, ahorra costos al separar contenido y presentación para varios dispositivos y suma prestigio social (página 20).

Independencia de dispositivos e internacionalización

Estos temas están en las preguntas de la Práctica 8 con respuesta de la cátedra.

Independencia de dispositivos. Para el usuario da acceso universal. Para el desarrollador, un único desarrollo sirve para muchas aplicaciones (Algunas respuestas, página 1).

La idea es que la información esté siempre disponible y accesible, sea cual sea el dispositivo, y que la Web no se fragmente en espacios para dispositivos concretos. Busca mejorar la experiencia del usuario y reducir costos, porque se programa una sola vez y se evita duplicar información. Para lograrla hacen falta lenguajes de etiquetado estándar que funcionen en muchos dispositivos, nuevas técnicas de autor y una mejor negociación de contenido entre el agente de usuario y el servidor, con datos del contexto de envío como las preferencias del usuario y las características del dispositivo (Algunas respuestas, página 1).

Internacionalización. Es el proceso para diseñar sitios adaptables a distintos idiomas y regiones sin cambiar el código. Usa lang, hreflang, UTF-8 y el charset del Content-Type (páginas 1 y 2).

Cómo funciona, según la misma respuesta (páginas 2 a 4).

  • Los usuarios necesitan procesar la información en su idioma, sistema de escritura, sistema de medida y calendario. Por eso se usan identificadores de idioma y lugar.
  • HTML usa el atributo lang y XML usa xml:lang. El idioma de la página se declara al inicio, como <html xmlns="http://www.w3.org/1999/xhtml" lang="es">, y se marca cada cambio de idioma dentro del texto.
  • El código lleva primero el idioma y, si se quiere, el país, como en o en-US. En un enlace a una página en otro idioma se usa hreflang.
  • La codificación transforma bits en caracteres. Conviene servir todo en UTF-8, que representa Unicode para muchos idiomas, y declararla. En HTTP va como Content-Type: text/html; charset=UTF-8, en XML como <?xml version="1.0" encoding="UTF-8" ?> y en XHTML con un meta dentro de head.

La Práctica 8 pregunta también por los conceptos clave del diseño web internacional. La respuesta de la cátedra los lista (Algunas respuestas, página 4).

  • Codificación. Usar Unicode siempre que se pueda y declarar siempre la codificación.
  • Escapes. Usar caracteres en lugar de escapes, como &aacute;, siempre que se pueda.
  • Idioma. Declarar el idioma del documento e indicar los cambios internos.
  • Presentación y contenido. Usar hojas de estilo para la presentación y las etiquetas para la semántica.
  • Imágenes, animaciones y ejemplos. Ver si se pueden traducir y si tienen alguna influencia cultural inadecuada.
  • Formularios. Usar una codificación adecuada en el formulario y en el servidor, y admitir formatos locales de nombres, direcciones y fechas.
  • Autoría de texto. Texto simple y conciso, con cuidado al armar oraciones con varias cadenas.
  • Navegación. En cada página, una navegación visible hacia las versiones localizadas, en el idioma de llegada.
  • Texto de derecha a izquierda. En XHTML, dir="rtl" en la etiqueta html.

Localización. Es la adaptación a un mercado destinatario: formatos, moneda, teclado, ordenamiento, símbolos, referencias culturales y exigencias legales (página 5).

Se la confunde con la traducción, pero es más compleja. Puede exigir rehacer la lógica, el diseño visual o la presentación si la forma de hacer negocios o de aprender en el destino es muy distinta (página 5).

La internacionalización, en cambio, es el diseño y desarrollo de un producto para que se pueda localizar fácilmente. Implica eliminar obstáculos a la localización, como usar Unicode y controlar la concatenación de cadenas; habilitar funciones que quizás se usen recién al localizar, como el texto bidireccional; preparar el código para las preferencias locales, como fechas, calendarios y números; y separar del código los elementos localizables. No incluye traducir el contenido (páginas 5 y 6).

En criollo

Internacionalizar es dejar el sitio preparado. Localizar es adaptarlo a un país concreto.

Cookies

¿Qué son las cookies? ¿Con qué función se crean y qué parámetros tiene?Final 15/03/2023

Son pequeñas informaciones de texto que se pueden almacenar en el navegador del visitante. Se crean con setcookie. El único parámetro obligatorio es el nombre. Los otros son valor, caducidad, ruta, dominio, seguro y solo http. Un ejemplo es setcookie("persona",$nombre,time()+86400*365);.

Fuente: apunte Teoría de Cookies, páginas 3, 7 y 11.

Solo guardan textos, de hasta 1 K, y tienen fecha de caducidad (página 4). Volver a definir una cookie existente borra la anterior (página 8).

Si la consigna pide explicar los parámetros, esto dice cada uno (página 11).

ParámetroQué es
NombreEl nombre de la cookie. Es el único obligatorio
ValorLa cadena que va a guardar
CaducidadUn timestamp con la fecha en que vence. Lo normal es time() más los segundos que tiene que durar
RutaDónde se puede usar dentro del dominio. Por defecto, el directorio donde se creó y sus subdirectorios. Con "/" vale en todo el dominio
DominioEl subdominio donde se puede leer. Se puede hacer visible para todos los subdominios del sitio
SeguroSi es true, la cookie solo viaja por HTTP seguro
Solo httpSi es true, solo se accede por las cabeceras HTTP y JavaScript no la puede leer. Se agregó en PHP 5.2.0

setcookie devuelve true si pudo enviarla, pero eso no dice si el navegador la aceptó (página 12).

La utilidad principal es reconocer al navegador cuando vuelve, para adaptar el sitio a sus preferencias, como el idioma, los colores o formularios ya completados (página 6). Dos usos típicos son un contador de visitas y guardar el perfil del usuario (página 5). Con HTML solo no se puede trabajar con cookies, hace falta un lenguaje como JavaScript o PHP (página 6).

El apunte marca tres cuidados. Las cookies plantean un problema de privacidad, porque registrar el perfil de alguien puede ser un abuso de información (página 6). Una variable del script con el mismo nombre que la cookie tiene prioridad, y PHP no da error (página 9). Y como no todos los navegadores las aceptan y se pueden bloquear, son un complemento y no una fuente infalible (página 10).

HTML5 agrega otra forma de guardar datos en el navegador. localStorage guarda sin fecha de caducidad, al menos 5 MB, y los datos no viajan al servidor en cada pedido. sessionStorage tiene los mismos métodos, setItem y getItem, pero lo guardado se borra al cerrar el navegador. Los dos se usan con JavaScript (Conceptos fundamentales de HTML, páginas 47 a 50).

Sesiones

¿Qué son las sesiones?Parcial de teoría, Tema 1, 06/06/2016 Plan viejo

Son un conjunto de variables almacenadas en el servidor, únicas para cada entidad que accede a la página. Las identifica una cookie o el SID. Son seguras porque los valores quedan en el servidor. Las cookies, en cambio, están en la PC del usuario y pueden desactivarse.

Fuente: apunte Teoría de Sesiones, páginas 2, 3, 6 y 9.

El apunte da otra definición. Es una estructura de datos guardada en el servidor, con información del seguimiento de cada cliente (página 2). Permite registrar variables que se conservan durante toda la visita, referenciadas por un identificador único de cada visitante. Se guardan en un archivo del servidor que se crea al guardar la variable (página 3).

  • Cinco métodos principales. Abrir la sesión, definir una variable, darle un valor, obtener el valor y cerrar la sesión (página 4).
  • Dónde se usan. En aplicaciones cliente-servidor, como ftp, telnet y las aplicaciones web (página 4).
  • Para qué sirven. Para conservar datos a lo largo de los accesos siguientes y armar páginas más personalizadas (página 5).
  • La constante SID. Tiene el nombre y el id de la sesión con la forma name=ID, o una cadena vacía si el id ya viaja en una cookie de sesión. Por eso se puede poner siempre en las URL (páginas 6 a 8).

El ejemplo de seguridad del apunte es una variable logueado en la sesión. Si estuviera en una cookie, el cliente podría cambiar su valor. Guardar el usuario y la contraseña en cookies, además, los haría viajar de forma poco segura y quedarían en la PC del cliente (página 9).
