    1° parcial

    La práctica en PC

    Lo que piden los 4 temas1° parcial 09/06/2025 (temas Auto, Moto, Celular) y 08/06/2026 (tema Médico)
    1. Una solución .NET con dos proyectos, ApellidoNombre.Dominio, del tipo Biblioteca de Clases, y ApellidoNombre.Consola, del tipo Aplicación de Consola.
    2. Una clase base abstracta que ya viene escrita y copiás.
    3. Una clase derivada con una propiedad nueva, un constructor que llama al constructor de la clase superior y una sobreescritura de ToString que invoca al método de la clase superior.
    4. Una clase con métodos estáticos de búsqueda. Uno con LINQ y otro equivalente iterando sobre la lista.
    5. En el Main, una lista del tipo base, tres objetos de la clase derivada, las dos búsquedas y mostrar el resultado con ToString.

    El tema Médico suma un enum y un método más, que filtra con LINQ y devuelve una lista.

    Las reglas de la entrega1° parcial 09/06/2025 y 08/06/2026
    • Se evalúa el «correcto funcionamiento (compilación/ejecución sin errores), uso de convenciones, formateo, estándares y buenas prácticas».
    • «Los nombres de la/los solución/proyectos/namespaces deben tener de prefijo su ApellidoNombre». El ejemplo que da es PerezJuan.X.
    • «El entregable debe estar zipeado y nombrado como ApellidoNombre.zip».

    Que un proyecto vea al otro. «Antes de escribir código que trabaje con un componente externo, el proyecto debe contener en primer lugar una referencia a dicho componente» (Unidad 1, Capítulo 2, Teoría, pág. 13). El laboratorio de POO agrega desde el proyecto de consola la referencia al proyecto Class Library, en la pestaña Projects, y después pone su using en program.cs (Unidad 2, Capítulo 2, Laboratorio POO, págs. 1 y 2).

    Enumeraciones. Una enumeración es «un tipo por valor que permite definir un conjunto de constantes con nombre». Se declara con enum. El primer enumerador vale 0 y cada uno suma 1. El tipo subyacente es int por defecto, y para pasarlo a entero hace falta una conversión explícita, int x = (int)Days.Sun; (Unidad 2, Capítulo 1, Teoría, págs. 16 y 17).

    Un enum en la práctica1° parcial 08/06/2026

    El tema Médico pide agregar un tipo enumerado y una propiedad de ese tipo.

    LINQ. Se escribe de dos formas, que dan lo mismo (Presentación de la Unidad 2, Capítulo 3, diapositiva 14).

    var contacts =
    from c in customers
    where c.City == "Hove"
    select new { c.Name, c.Phone };

var contacts =
    customers
    .Where(c => c.City == "Hove")
    .Select(c => new { c.Name, c.Phone });

    Una query expression «empieza con from, termina con select o group by» (diapositiva 21). Los operadores que nombra la diapositiva 22 son Select, Where, Distinct, Any, All, Join, Group By, Count, Sum, Min, Max, Skip, Take, Union, Intersect, Except y Order By.

    Algo que las diapositivas no muestran

    Los ejemplos de la presentación devuelven colecciones. No hay uno que traiga un solo objeto, que es lo que pide la búsqueda de los parciales. Practicá eso con la documentación de Microsoft antes de rendir.

    Un «conjunto de clases que permite desarrollar aplicaciones basadas en Windows», orientado a eventos (Presentación de la Unidad 3, diapositivas 3 y 8). La jerarquía es Object, Component, Control y Form, la ventana a la que le añadís controles (diapositiva 6). La aplicación arranca con Application.Run(new Form1()) (diapositiva 15). ShowDialog devuelve el valor de la propiedad DialogResult del formulario (Unidad 3, Laboratorio 1, pág. 8).

    Aprobación directa

    Lo que pide siempreAprobación directa 13/10/2025 y 05/10/2026

    El enunciado dice que desarrolles una aplicación .NET «aplicando los principios de arquitectura, buenas prácticas y lineamientos vistos en clase y aplicados en el TPI», considerando lo siguiente.

    • Capa de Presentación: «puede elegir Escritorio (Windows Forms) o Web (Blazor). Debe comunicarse con los servicios mediante una API Rest».
    • Servicios: «todos deben ser asíncronos y se deben poder testear mediante swagger».
    • Acceso a datos: «Utilice el patrón repositorio para resolver el acceso a datos mediante EF». La base debe crearse con el nombre pedido, por ejemplo dbReceta, «siguiendo los mecanismos que provee EF».
    • Criterios: «correcto funcionamiento (compilación/ejecución sin errores), uso de convenciones solicitadas, estética visual de las pantallas, estándares y buenas prácticas».
    Las 4 consignasAprobación directa 13/10/2025 y 05/10/2026
    1. Estructura y entidad. Una carpeta ApellidoNombre. Cada proyecto y namespace respeta [Apellido].[NombreProyecto], por ejemplo Perez.Presentacion. La entidad trae Id entero, autoincremental y clave primaria, datos propios y un Estado de texto.
    2. API de servicios. Tres endpoints. Recuperar registros según el estado, agregar un registro que se crea siempre en el primer estado, y pasarlo al segundo estado.
    3. Validaciones. Campos obligatorios, un rango numérico y una regla de fechas.
    4. Presentación. Un listado con un control tipo lista para filtrar por estado y un botón que aplica el filtro. Un alta que se abre con un botón «Agregar», donde el usuario no elige el estado, que lo pone el servicio. Y en el listado, la acción de pasar de estado.

    La regla de fechas cambia

    En Alquiler y Promoción, FechaInicio debe ser inferior a FechaFin. En Receta, FechaEmision debe ser igual a la fecha de hoy o el día previo. Leé la tuya con cuidado.

    Lineamientos de la cátedra para el examenNotas de la cátedra sobre un examen del 30/10/2024

    En el Drive hay notas de la cátedra sobre un examen de una inmobiliaria. No está el enunciado, pero sí lo que se aceptaba. Citas textuales.

    • Nombres. «Se podrían haber usado otros nombres en la medida que sean representativos.» Para el dominio, también AppCore o Core. Para presentación, UI, Escritorio, Desktop, Winform o Presentación. Para la API, Endpoints, Api o PubliAPI.
    • Más proyectos. «Era válido crear otros proyectos adicionales para mejorar el desacoplamiento», pero «no las recomendamos para el parcial ya que agregan complejidad y siempre vamos a tener un tiempo acotado».
    • DTO. Crear un DTO «busca desacoplar 100% el backend del frontend. A los fines del examen era válido compartir la entidad». Y «es importante que el alumno comprenda el impacto de acoplamiento que esto genera desde lo conceptual».
    • Validaciones. Del lado del cliente o del servidor, «para el alcance del parcial ambas opciones son válidas». Pero «nuestra API de servicios nunca puede confiarse de que la presentación va a realizar estas validaciones».
    • Configuración. La URL de los endpoints y el string de conexión «en un ejemplo real se recomienda moverlos a un archivo de configuración».
    • Depuración. Se configuró «que arranquen inicialmente el proyecto de presentación y el web api». Se cambia con botón derecho en la solución, en los proyectos de inicio.

    El controlador del laboratorio 2 no es asíncrono

    Usa Find, ToList y SaveChanges. El examen pide que todos los servicios sean asíncronos. El laboratorio 1 dice «Utilizar flujos asíncronos (async / await) para exponer cada una de las operaciones» y usa FindAsync y SaveChangesAsync.

    Asincronía

    PiezaQué es
    Task y Task<T>Modelan las operaciones asincrónicas
    async«Convierte un método en un método asincrónico», y permite usar await en su cuerpo
    await«Se suspende el método invocado y se cede el control de vuelta al autor de la invocación hasta que se completa la tarea esperada»

    Fuente: Presentación de Programación Asíncrona, diapositivas 4 y 7. Las reglas de la diapositiva 9 son que un método async lleve un await en el cuerpo, que su nombre termine en «Async» y que async void se use solo para manejadores de eventos. Y await solo puede usarse dentro de un método asincrónico (diapositiva 7).
