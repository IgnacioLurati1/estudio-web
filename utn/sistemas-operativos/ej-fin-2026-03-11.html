    1. 1

      Multiplexar un recurso en el tiempo significa que...

      Se tomó: Finales 07/02/24 y 11/03/26, adaptada

      En el tiempo son turnos, por ejemplo la CPU. En el espacio cada uno tiene una parte, por ejemplo la memoria.

    Propuesta de respuesta

    Respuesta no verificada. La propuso Luta Studios con inteligencia artificial y ningún docente la revisó. Puede tener errores.

    1. RAID 5 reparte los datos en bandas con la paridad distribuida entre todos los discos. Su ventaja principal es que evita el cuello de botella de RAID 4, donde la paridad está en un disco dedicado y cada escritura lo toca. Necesita al menos 3 discos y soporta la falla de uno. Si fallan 2, se pierde todo.

    2. En el material, la autenticación es uno de los cuatro requisitos de la seguridad. Es que el sistema pueda verificar la identidad de los usuarios, saber que sos quien decís ser. La palabra «autorización» no aparece en la teoría del Drive. Lo que el material trae para decidir qué puede hacer cada uno ya identificado es la matriz de acceso, con los derechos de cada sujeto sobre cada objeto. La diferencia es esa. Primero se verifica quién es y después qué puede hacer.

    3. El SO administra los recursos y los reparte entre los programas de dos formas.

    • En el tiempo: los programas o usuarios toman turnos para usar el recurso. Quién sigue y por cuánto tiempo lo decide el SO. Ejemplos, la CPU, o la impresora cuando varios mandan trabajos y se imprimen de a uno.
    • En el espacio: cada uno recibe una parte del recurso. Ejemplos, la memoria principal, que se divide entre varios programas a la vez, o el disco duro, con archivos de varios usuarios.

    4. Se usan tres semáforos. llenas cuenta las ranuras ocupadas del búfer y empieza en 0. vacias cuenta las libres y empieza en N. mutex asegura que productor y consumidor no toquen el búfer a la vez, y empieza en 1.

    #define N 100
semaforo mutex = 1;   /* exclusión mutua sobre el búfer */
semaforo vacias = N;  /* ranuras libres */
semaforo llenas = 0;  /* ranuras ocupadas */

void productor(void) {
  int elemento;
  while (TRUE) {
    elemento = producir_elemento();
    down(&vacias);    /* si no hay lugar, se duerme */
    down(&mutex);     /* entra a la región crítica */
    insertar_elemento(elemento);
    up(&mutex);       /* sale de la región crítica */
    up(&llenas);      /* hay un elemento más, despierta al consumidor */
  }
}

void consumidor(void) {
  int elemento;
  while (TRUE) {
    down(&llenas);    /* si está vacío, se duerme */
    down(&mutex);
    elemento = quitar_elemento();
    up(&mutex);
    up(&vacias);      /* hay un lugar más, despierta al productor */
    consumir_elemento(elemento);
  }
}

    llenas y vacias sincronizan, para que el productor se duerma con el búfer lleno y el consumidor con el búfer vacío. mutex da la exclusión mutua. Como down y up son atómicos, ninguna señal de despertar se pierde, que era el problema de la variable de conteo sin protección. El orden de los down importa. Si el productor hiciera down(&mutex) antes que down(&vacias) con el búfer lleno, se dormiría con el mutex tomado y el consumidor no podría entrar nunca.

    5. La denegación de servicio (DoS) es un ataque activo que impide el uso normal de las comunicaciones. Ataca la disponibilidad, como la amenaza de interrupción. Para lanzarlos se usan zombies, computadoras ajenas tomadas para eso. El principio de privilegio mínimo no aparece en la teoría del Drive, así que acá no va una definición.
