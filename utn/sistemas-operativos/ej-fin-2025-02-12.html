    Enunciado

    1- Que es una tabla de páginas y para que se usa.

    2- Definir región crítica y condiciones para evitar que dos procesos entren en sus regiones críticas al mismo tiempo (condiciones para evitar condiciones de carrera).

    3- Aspectos de diseño para aprovechar la configuración de un cluster.

    4- Que recursos se involucran en un interbloqueo, por qué y que eventos se realizan al solicitar un recurso.

    5- La administración de recursos incluye el multiplexaje de los mismos, explicar las dos formas posibles.

    Propuesta de respuesta

    Respuesta no verificada. La propuso Luta Studios con inteligencia artificial y ningún docente la revisó. Puede tener errores.

    1. La dirección virtual se divide en número de página virtual (bits de mayor orden) y desplazamiento (menor orden). El número de página es el índice en la tabla de páginas. De la entrada sale el número de marco, que se pega al desplazamiento para dar la dirección física. Así la MMU traduce cada dirección virtual a una física.

    Cada entrada tiene estos campos.

    • Número de marco de página: el campo más importante.
    • Bit presente/ausente: si es 0, acceder produce un fallo de página.
    • Bits de protección: qué accesos se permiten (lectura, escritura, ejecución).
    • Bit de modificada (sucia): lo pone el hardware al escribir. Si está sucia, hay que grabarla en el disco antes de reclamar el marco.
    • Bit de referenciada: se pone con cada acceso, de lectura o escritura. Ayuda a elegir a quién desalojar.
    • Bit de caché deshabilitada: para páginas asociadas a registros de dispositivos.

    2. La región crítica (o sección crítica) es la parte del programa que accede a la memoria compartida. Hay una condición de carrera cuando dos o más procesos leen o escriben datos compartidos y el resultado final depende de quién se ejecute primero. Para evitarla se necesitan cuatro condiciones.

    1. No puede haber dos procesos a la vez dentro de sus regiones críticas.
    2. No se pueden hacer suposiciones sobre las velocidades ni el número de CPU.
    3. Ningún proceso que esté fuera de su región crítica puede bloquear a otros.
    4. Ningún proceso espera para siempre para entrar.

    La primera es la exclusión mutua: si un proceso usa un dato compartido, los otros quedan excluidos.

    3. Son servicios deseables, cada uno en su versión «único», para que el usuario vea una sola máquina.

    • Un único punto de entrada.
    • Una única jerarquía de directorios.
    • Un único punto de control.
    • Una única red virtual.
    • Un único espacio de memoria.
    • Un único sistema de control de trabajos.
    • Una única interfaz de usuario.
    • Un único espacio de E/S.
    • Un único espacio de procesos.
    • Puntos de control: se guarda periódicamente el estado del proceso, para seguir en otro nodo si este falla.
    • Migración de procesos: un proceso pasa de un nodo a otro para balancear la carga.

    4. Para usar un recurso hay tres eventos, en orden.

    1. Solicitar el recurso. Si no está disponible, el proceso espera.
    2. Usarlo.
    3. Liberarlo.

    Los recursos son de dos tipos. Uno apropiativo se le puede quitar al proceso sin efectos dañinos, como la memoria. Uno no apropiativo no, porque quitarlo hace fallar el cómputo, como una grabadora de CD. Los interbloqueos involucran recursos no apropiativos. Con uno apropiativo el bloqueo se rompe quitándoselo a quien lo tiene. Por eso intervienen los no apropiativos. Si el recurso se pudiera quitar sin daño, el SO lo sacaría y la espera circular se cortaría. Es la condición de no apropiación de Coffman.

    5. El SO administra los recursos y los reparte entre los programas de dos formas.

    • En el tiempo: los programas o usuarios toman turnos para usar el recurso. Quién sigue y por cuánto tiempo lo decide el SO. Ejemplos, la CPU, o la impresora cuando varios mandan trabajos y se imprimen de a uno.
    • En el espacio: cada uno recibe una parte del recurso. Ejemplos, la memoria principal, que se divide entre varios programas a la vez, o el disco duro, con archivos de varios usuarios.
