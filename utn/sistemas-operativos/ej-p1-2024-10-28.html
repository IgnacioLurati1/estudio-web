    Tema 1, regularización

    1. La multiprogramación es cambiar a otro trabajo cuando el actual tiene que esperar. Aumenta el uso de la CPU porque siempre hay algo para ejecutar. Para eso hay que tener varios programas a la vez en memoria. En el gráfico, los cuatro programas están en memoria y se turnan la CPU. Mientras uno corre, los otros esperan.

    2. Hay cuatro eventos que crean procesos.

    1. El arranque del sistema.
    2. Una llamada al sistema de creación de procesos, hecha por otro proceso.
    3. Una petición del usuario, como abrir un programa.
    4. El inicio de un trabajo por lotes.

    3. Los comandos, con un ejemplo de cada uno.

    OperaciónComando

    Crear un enlace simbólicoln -s informe.txt informe-blando

    El enlace duro tiene el mismo inodo que el original y solo se crea dentro de la misma partición. El simbólico apunta al nombre, tiene su propio inodo y puede cruzar particiones. Ojo con rm -r, que borra todo sin pedir confirmación.

    Tema 1, aprobación directa

    5. Beneficios.

    • Escalabilidad absoluta: se puede armar uno más potente que la mayor máquina.
    • Escalabilidad incremental: se agregan sistemas de a poco, a medida que hace falta.
    • Alta disponibilidad: cada nodo es una computadora completa, así que la falla de uno no hace perder el servicio.
    • Relación precio/prestaciones: igual o mayor poder que una máquina grande, a menor costo.

    Consideraciones. Son los aspectos de diseño, para que el cluster se vea como una sola máquina.

    Son servicios deseables, cada uno en su versión «único», para que el usuario vea una sola máquina.

    • Un único punto de entrada.
    • Una única jerarquía de directorios.
    • Un único punto de control.
    • Una única red virtual.
    • Un único espacio de memoria.
    • Un único sistema de control de trabajos.
    • Una única interfaz de usuario.
    • Un único espacio de E/S.
    • Un único espacio de procesos.
    • Puntos de control: se guarda periódicamente el estado del proceso, para seguir en otro nodo si este falla.
    • Migración de procesos: un proceso pasa de un nodo a otro para balancear la carga.

    Por ejemplo, con un único punto de entrada el usuario se conecta al cluster y no a un nodo en particular. Es el cluster el que decide en qué nodo atenderlo, y si ese nodo falla el usuario no tiene que cambiar nada.

    6. El invitado sondea el hardware para ver qué dispositivos hay. Esas sondas interrumpen al hipervisor, que responde con los dispositivos reales. El invitado carga sus drivers y, cuando opera sobre los registros del dispositivo, esas instrucciones son sensibles y las atrapa el hipervisor, que copia los valores. El hipervisor suele crear un archivo o una región del disco como disco físico de la máquina virtual.

    Tema 2, regularización

    1. Un SO embebido (integrado) no acepta software instalado por el usuario. Todo el software está en la ROM.

    2. | Motivo | Tipo | Ejemplo | |---|---|---| | Salida normal | Voluntaria | Terminó su trabajo. Un compilador termina de compilar el programa | | Salida por error | Voluntaria | El propio proceso descubre un error, por ejemplo un parámetro mal ingresado, como pedir que compile un archivo que no existe | | Error fatal | Involuntaria | Suele ser un error del programa, como dividir por cero o acceder a memoria que no existe | | Eliminado por otro proceso | Involuntaria | Otro proceso llama al sistema para matarlo, como cuando el usuario lo cierra con kill |

    3. La segmentación divide programas y datos en espacios de direcciones lógicamente independientes, los segmentos, de tamaño variable. Se inventó para ayudar a compartir y proteger. La paginación se inventó para obtener un gran espacio de direcciones lineal sin comprar más memoria física. La segmentación se inventó para dividir programas y datos en espacios de direcciones lógicamente independientes, y ayudar a compartir y proteger.

    ConsideraciónPaginaciónSegmentación
    El programador sabe que se usaNoSí

    El espacio total puede superar la memoria físicaSíSí
    Procedimientos y datos se distinguen y protegen por separadoNoSí

    La segmentación pura sufre fragmentación externa (efecto tablero de ajedrez), que se maneja con compactación.

    Tema 2, aprobación directa

    5. Ocurre cuando el programa referencia una página que no está en memoria, o sea con el bit presente/ausente en 0. La MMU lo detecta y hace un trap al SO. La secuencia del libro es esta.

    1. El hardware hace un trap al kernel y guarda el contador de programa.
    2. Una rutina en ensamblador guarda los registros.
    3. El SO descubre cuál es la página virtual que se necesita.
    4. Comprueba que la dirección sea válida y la protección consistente. Si no, el proceso recibe una señal o muere.
    5. Busca un marco libre. Si no hay, corre el algoritmo de reemplazo y elige una víctima.
    6. Si el marco elegido está sucio (bit de modificada en 1), se planifica su escritura en el disco y se cambia de proceso mientras tanto.
    7. Se planifica la lectura de la página necesaria desde el disco.
    8. Cuando llega, se actualizan las tablas y el marco queda normal.
    9. Se reinicia la instrucción que falló y se recargan los registros.

    En el paso 7 el SO no se queda esperando el disco. Cambia de proceso y vuelve cuando la lectura termina y llega la interrupción.

    6. - Tipo 1: corre directo sobre el hardware, en modo kernel. Soporta varias copias del hardware, las máquinas virtuales, parecido a un SO con sus procesos. Cada máquina virtual corre como un proceso de usuario con un SO invitado, que cree estar en modo kernel (modo de kernel virtual). Cuando el invitado ejecuta una instrucción sensible, hay un trap al hipervisor, que decide cómo emularla.

    • Tipo 2: es un programa de usuario que corre sobre un SO anfitrión e interpreta el conjunto de instrucciones, como VMware. Las instrucciones sensibles se reemplazan por llamadas a procedimientos del hipervisor, que las emula. Eso es la traducción binaria.

    La diferencia está en qué corre sobre el hardware. En el tipo 1 es el hipervisor, y no hay un SO debajo. En el tipo 2 es un SO anfitrión común, y el hipervisor es un proceso más de ese SO.

    7. - Escalabilidad absoluta: se puede armar uno más potente que la mayor máquina.

    • Escalabilidad incremental: se agregan sistemas de a poco, a medida que hace falta.
    • Alta disponibilidad: cada nodo es una computadora completa, así que la falla de uno no hace perder el servicio.
    • Relación precio/prestaciones: igual o mayor poder que una máquina grande, a menor costo.
