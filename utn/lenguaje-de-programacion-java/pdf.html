Para entender

Una electiva donde el parcial te pide escribir código Java a partir de un diagrama de clases. El Drive trae las hojas de examen, pero no trae teoría de la cátedra.

Resumen no juzgado. Todavía nadie evaluó si alcanza para estudiar solo con esto.

Qué podés esperar de este resumen

En el Drive no hay programa, apunte ni clases. Hay exámenes y trabajos de alumnos. Por eso acá vas a encontrar qué se pide y cómo viene, con su hoja. La teoría de Java no se completó de memoria, porque cada cátedra pide las cosas a su manera. Lo que falta está en esta lista.

La idea general

Te dan un diagrama de clases y reglas de negocio. Lo pasás a código Java y programás un método que calcula algo, como un sueldo o una ganancia. La hoja pide que lo hagas con herencia, polimorfismo y redefinición.

Pensá el parcial como una traducción. El diagrama dice qué clases hay y cómo se relacionan. Las reglas dicen qué cuenta hacer. Tu código tiene que respetar las dos cosas.

El ejercicio 1

Lo que hay que entregar, con las mismas palabras en las 5 hojasParciales y recuperatorios de 2024 a 2026

«Construya el código fuente en java para el diagrama de clases anexo.» La hoja pide:

  • Definición de las clases, herencia y atributos.
  • Relaciones entre las clases. «Queda librado a su elección en cuál clase representar las variables y métodos necesarios para la asociación.»
  • Los métodos necesarios para modelar esas relaciones y para ejecutar el método pedido.

El método «debe programarse utilizando los conceptos del paradigma de orientación a objeto utilizando herencia, polimorfismo y redefinición».

Las 5 hojas traen esas tres palabras en negrita. Al terminar, revisá tu código buscándolas.

Las hojas también dicen que «pueden desarrollar métodos intermedios que consideren necesarios o convenientes». O sea que podés partir el cálculo en métodos más chicos.

Herencia, redefinición y polimorfismo

Las hojas piden las tres palabras y ninguna las define. Esto es lo que se puede mostrar con el material.

Herencia

Se escribe con extends. Está en las hojas de 2014 y en el trabajo final de 2020.

public class Proveedor extends EntidadMadre {

    private String razonSocial;
    private String cuit;

Documentación del trabajo final de alumnos, 2020, página 29.

En el diagrama de ese trabajo, EntidadMadre tiene id, domicilio, teléfono y correo. Proveedor suma solo razonSocial y cuit. Su constructor le pasa los datos comunes a la clase de arriba con super.

super(domicilioCalle, domicilioNumero, domicilioPiso, domicilioDepartamento,
        telefono, correoElectronico);

this.razonSocial = razonSocial;
this.cuit = cuit;

Polimorfismo

El Drive no trae una definición ni un ejemplo explicado. La hoja de 2014 tiene la línea A unObj = new B(); dentro de una consigna. Esa consigna queda para que la pienses vos, con la hoja al lado.

Lo que se pide y el material no explica

Estos temas hacen falta para el parcial y ningún archivo del Drive los enseña. Estudialos de lo que dé tu comisión o de la documentación oficial de Java.

  • Qué son la herencia, el polimorfismo y la redefinición, con su definición formal.
  • Clases y métodos abstractos.
  • Cómo se programa una relación entre clases con una colección, y en cuál clase conviene ponerla.
  • ArrayList y LinkedList: cómo se crean, se recorren y se les agregan elementos.

De la página a la base

La página crea el controlador y recorre lo que devuelve.

ControladorProveedor cp = new ControladorProveedor();
ArrayList<Proveedor> lista = cp.buscarTodos();

Documentación, página 19.

El controlador le pasa cada operación a la clase de datos.

public class ControladorProveedor {

    DatosProveedor datos = new DatosProveedor();

    public void alta(Proveedor proveedor) throws SQLException, Excepcion {
        datos.alta(proveedor);
    }

Documentación, página 24.

La clase de datos ejecuta la consulta y arma un objeto por cada fila.

sentenciaSQL = Conexion.crearInstancia().abrirConexion().prepareStatement("SELECT * FROM proveedores");

resultado = sentenciaSQL.executeQuery();

while (resultado.next()) {
    Proveedor proveedor = new Proveedor();
    proveedor.setId(resultado.getInt("id"));
    proveedor.setRazonSocial(resultado.getString("razonSocial"));
    // ...los demás campos
    listado.add(proveedor);
}

Documentación, página 25. Los campos del medio están resumidos.

Para guardar, la sentencia lleva signos de pregunta y cada valor se carga por su posición.

sentenciaSQL.setString(1, proveedor.getRazonSocial());
sentenciaSQL.setString(2, proveedor.getCuit());
// ...hasta el 8
sentenciaSQL.executeUpdate();

Documentación, página 26.

Excepciones en el código del trabajo

Cada método de datos declara throws y tiene dos bloques try. El primero hace la consulta. El segundo cierra la conexión. Los comentarios son del grupo.

// Estos 2 "Catch" son para el "Try" principal (donde está la consulta a la base
// de datos)
catch (SQLException excepcion) {
    throw new SQLException("Algo salió mal intentando buscar los proveedores en la base de datos", excepcion);
}
catch (Excepcion excepcion) {
    throw new Excepcion(excepcion, "Algo salió mal intentando buscar los proveedores");
}

La carpeta TPI

Otra carpeta del Drive, sin fecha ni consigna, trae dos bases casi iguales con una tabla personajes (vida, energia, defensa, evasion, puntos) y una nota de pasos. Los programas de esa carpeta no se abrieron para este resumen.

La nota dice:

  1. Agregar librerías, conector.
  2. Crear servlet.
  3. Crear JSP.
  4. Corregir la organización de la página, con un botón de atacar y defender único y un campo para la energía.
  5. Código, con el camino «index - servlet - jsp y vuelve», usando métodos POST y GET.

No se sabe si ese trabajo se sigue pidiendo.
